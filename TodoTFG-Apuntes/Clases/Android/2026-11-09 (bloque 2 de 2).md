## 2. Conceptos y patrones

- **Arquitectura por feature**: `features/pokemon/data/{local, model, remote, repository}` y `ui`; `core/di` con `AppModule`, `NetworkModule` y `PokeApplication`.
- **Dos data sources detrás de un repositorio**: `RemoteDataSource` (API) y `LocalDataSource` (de momento en memoria; la carpeta `local` deja el sitio preparado para Room más adelante).
- **Offline-first / fuente única de verdad**: la UI observa siempre el `Flow` **local**, y `refresh()` descarga del remoto y guarda en local.
- **Interfaz + implementación** en todas las capas, atadas con `@Binds @Singleton` en un módulo `interface`.
- **Backing property** `_pokemons` (privada y mutable) frente a `pokemons` (pública, `Flow` de solo lectura).
- `val` / `var` y `List` / `MutableList`: una `val` de tipo `MutableList` no se puede reasignar, pero su contenido sí cambia (`clear()`, `addAll()`).
- **Flow**: el constructor `flow { emit(...) }` y la propiedad `Flow<List<T>>` en una interfaz.
- **Corrutinas**: una `suspend` solo se puede llamar desde una corrutina o desde otra `suspend`.
  - `init` no es `suspend`.
  - `withContext` es `suspend`, así que no sirve dentro de `init`.
  - `runBlocking` bloquea el hilo; el profesor lo trata como solución provisional, que no es lo correcto en producción.
  - `CoroutineScope(Dispatchers.IO).launch` no bloquea.
- **ViewModel con `stateIn`**: el `StateFlow` sale de un `Flow` del repositorio con `map` y `stateIn(scope = viewModelScope, started = SharingStarted.WhileSubscribed(5_000L), initialValue = ...)`. Sustituye al patrón `_state` + `init { launch }`.
- `if / else` como expresión dentro de una lambda, y lambda con parámetro con nombre (`pokemon ->`) frente a `it`.
- **Rutas tipadas**: `savedStateHandle.toRoute<Routes.Detail>().id`.
- **Herramientas de Android Studio**: Refactor > Rename con vista previa, el *Usages* / *Implementation* que sale encima del código, depurador (breakpoints, variables, frames de corrutinas y de Compose, Resume), Run / Rerun, y cómo leer el contador de errores.

class PokemonInMemoryDataSource @Inject constructor() : PokemonLocalDataSource {
    private val _pokemons: MutableList<Pokemon> = mutableListOf()

    override val pokemons: Flow<List<Pokemon>> = flow {
        emit(_pokemons)
    }

    override suspend fun save(pokemons: List<Pokemon>) {
        _pokemons.clear()
        _pokemons.addAll(pokemons)
    }
}

    private val _remoteDataSource: PokemonRemoteDataSource,

## 5. Dudoso o ilegible

- **`javax.inject.Inject`**: una de las descripciones dice que "no es el que usa Hilt". **Eso está mal**: Hilt usa precisamente `javax.inject.Inject`. El error rojo de p1 37:56 era solo porque faltaba el import.
- **`observePokemon(id)`**: aparece en el repositorio y en el ViewModel de detalle a partir de p2 03:40, pero no hay ninguna captura donde se añada a `PokemonLocalDataSource`, a `PokemonInMemoryDataSource` ni a la interfaz `PokemonRepository`. No se sabe cómo está implementado.
- **Pantalla en blanco con `launch` y lista correcta con `runBlocking`** (p2 06:24–07:37): se ve el resultado, pero no la explicación del profesor. Mi interpretación, sin confirmar en clase: `flow { emit(_pokemons) }` solo emite una vez, en el momento en que se recoge. Si `refresh()` termina después, no vuelve a emitir y la lista se queda vacía. Con `runBlocking` los datos ya están guardados antes de que nadie recoja el flow. Probablemente esto prepara el paso a `MutableStateFlow` o a Room.
- **`init` del detalle**: usa `_state.value = ...`, pero `_state` está dentro del comentario `/** */`, y por eso da error (p2 04:39). No se ve si al final se borra ese `init`.
- **Bucle de `readAllPokemonImpl`**: el resto de la línea del `for` es ilegible.
- Final de `toModel()`: ilegible.
- `bottom` del `padding` de `AsyncImage`: ilegible.
- **Renderizado incompleto**: en p1 01:55 y p2 02:06 el emulador solo muestra un nombre ("bulbasaur", "charmeleon") arriba a la izquierda. No queda claro si es un renderizado a medias o un fallo.
- **Nombres de las funciones `@Binds`**: no siguen el mismo patrón (`bindsPokemon...` y `bindPokemonLocalDataSource`). Es solo un detalle de nombres y no afecta al funcionamiento.
