## 2. Conceptos y patrones
- **DataStore Preferences** para guardar preferencias sencillas, aquí el modo oscuro:
  - La clave tipada se crea con `booleanPreferencesKey("ui_mode")`.
  - Para leer, `dataStore.data.map { it[key] ?: false }`. El resultado es un `Flow<Boolean>` y lleva valor por defecto con el operador elvis.
  - Para escribir, `suspend` + `dataStore.updateData { prefs -> prefs.toMutablePreferences().also { it[key] = valor } }`.
  - **La lambda de `updateData` tiene que devolver las `Preferences`.** Por eso falla la versión con `val mutable = ...; mutable[uiMode] = mode`: la lambda no devuelve nada y el IDE marca error. Con `.also { }` sí se devuelve el objeto.
- **Capas de una feature:**
  - `data.local`: interfaz `SettingsDatasource` + implementación `SettingsDataStore`.
  - `repository`: interfaz `SettingsRepository` + `SettingsRepositoryImpl`.
  - `ui`: `SettingsScreen` + `SettingsViewModel`.
  - Cada capa solo conoce la interfaz de la capa de abajo. El repositorio no sabe nada de DataStore.
- **Hilt:**
  - Las clases se crean con `@Inject constructor`.
  - El módulo es un `interface AppModule` con `@Module @InstallIn(SingletonComponent::class)` y funciones `@Binds @Singleton` que atan cada interfaz a su implementación.
  - El ViewModel necesita **`@HiltViewModel`**. Sin él, `hiltViewModel()` intenta crearlo por reflexión con un constructor vacío y la app se cae (`NoSuchMethodException`).
- **Exponer el estado:**
  - `Flow` → `map` a una `data class SettingsUiState(val darkMode: Boolean = false)` → `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000L), initialValue)`.
  - En la pantalla se lee con `val uiState by viewModel.uiState.collectAsStateWithLifecycle()`, que necesita el import `androidx.compose.runtime.getValue`.
- **Eventos hacia el ViewModel:** `fun changeMode(mode) { viewModelScope.launch { repo.setMode(mode) } }`.
- **Componente reutilizable `ApplicationTopBar`:**
  - Recibe parámetros con valor por defecto (`showNavigation`, `showSettings`) y callbacks `() -> Unit = {}`.
  - Usa los slots `actions`, `navigationIcon` y `title` de `TopAppBar`, y necesita `@OptIn(ExperimentalMaterial3Api::class)`.
- **State hoisting / callbacks:** `onSettings` sube de la barra a `TaskListScreen`, de ahí al NavHost y allí se hace el `navigate`. Las pantallas no conocen el `navController`.
- **Pantalla con estado y pantalla sin estado:** hay dos `TaskListScreen` con el mismo nombre (sobrecarga):
  - La de "ruta" lleva `viewModel = hiltViewModel()` y un `when(uiState)` con `Initial`, `Loading` y `Loaded`.
  - La de presentación solo pinta, con parámetros `tasks`, `isLoading`, `isEmpty`, `onDelete` y `onSettings`.
- **Navigation Compose con rutas tipadas** y **grafos anidados** con `navigation<Grafo>(startDestination = ...)`. Se navega al grafo y este abre su pantalla inicial.
- **Iconos como código:** un `ImageVector.Builder` con `path(...)` y una propiedad perezosa (`_settings` como respaldo) en vez de un drawable XML.
- **Tema Material 3:** `lightColorScheme`/`darkColorScheme`, color dinámico desde Android 12 (`Build.VERSION_CODES.S`) e `isSystemInDarkTheme()`.
- Herramientas del IDE que salen en clase: Logcat con `package:mine`, la ayuda de parámetros, quick fix para importar, breakpoints y el contador de errores.

**`features/task/settings/data/local/SettingsDatasource.kt` y `SettingsDataStore.kt`**
```kotlin
interface SettingsDatasource {
    val darkMode: Flow<Boolean>
    suspend fun setMode(mode: Boolean)
}

class SettingsDataStore @Inject constructor(
    private val dataStore: DataStore<Preferences>
) : SettingsDatasource {

    private val uiMode = booleanPreferencesKey(name = "ui_mode")

    override val darkMode: Flow<Boolean>
        get() = dataStore.data.map { preferences -> preferences[uiMode] ?: false }

    override suspend fun setMode(mode: Boolean) {
        dataStore.updateData { preferences ->
            preferences.toMutablePreferences().also {
                it[uiMode] = mode
            }
        }
    }
}
```

```kotlin
@HiltViewModel
class SettingsViewModel @Inject constructor(
    private val settingsRepository: SettingsRepository,
) : ViewModel() {

    val uiState: StateFlow<SettingsUiState> = settingsRepository.settings
        .map<Boolean, SettingsUiState> { SettingsUiState(it) }
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(stopTimeoutMillis = 5_000L),
            initialValue = SettingsUiState()
        )

    fun changeMode(mode: Boolean) {
        viewModelScope.launch {
            settingsRepository.setMode(mode)
        }
    }
}

data class SettingsUiState(
    val darkMode: Boolean = false,
)
```

**`core/ui/navigation/Routes.kt` y `MainNavigation.kt`**
```kotlin
@Serializable
abstract class Routes(val route: String) {
    @Serializable object TaskFeature : Routes("task-feature")
    @Serializable object SettingsFeature : Routes("settings-feature")
    @Serializable object TaskList : Routes("task_list")
    @Serializable object TaskCreate : Routes("task_create")
    @Serializable class TaskDetail(val id: Int) : Routes("task_detail[$id]")
    @Serializable object Settings : Routes("settings")
}

@Composable
fun MainNavigation(modifier: Modifier = Modifier) {
    val navController = rememberNavController()
    val startDestination: Routes = Routes.TaskFeature
    NavHost(modifier = modifier, startDestination = startDestination, navController = navController) {
        navigation<Routes.TaskFeature>(startDestination = Routes.TaskList) {
            composable<Routes.TaskList> {
                TaskListScreen(
                    modifier = Modifier.fillMaxSize(),
                    toTaskCreate = { navController.navigate(Routes.TaskCreate) },
                    onSettings = { navController.navigate(Routes.SettingsFeature) }
                )
            }
            composable<Routes.TaskDetail> { TaskDetailScreen() }
            composable<Routes.TaskCreate> {
                TaskCreateScreen(onBack = { navController.popBackStack() })
            }
        }
        navigation<Routes.SettingsFeature>(startDestination = Routes.Settings) {
            composable<Routes.Settings> { SettingsScreen() }
        }
    }
}
```

**`TaskListScreen` (la que tiene estado, resumida)**
```kotlin
@Composable
fun TaskListScreen(
    modifier: Modifier = Modifier,
    viewModel: TaskListViewModel = hiltViewModel(),
    toTaskCreate: () -> Unit,
    onSettings: () -> Unit,
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    when (uiState) {
        TaskListUiState.Initial -> TaskListScreen(modifier = modifier, isEmpty = true, toTaskCreate = toTaskCreate, onSettings = onSettings)
        is TaskListUiState.Loaded -> {
            val tasks = (uiState as TaskListUiState.Loaded).tasks
            TaskListScreen(modifier = modifier, tasks = tasks, toTaskCreate = toTaskCreate, onDelete = {}, onSettings = onSettings)
        }
        TaskListUiState.Loading -> TaskListScreen(modifier = modifier, isLoading = true, toTaskCreate = toTaskCreate, onSettings = onSettings)
    }
}

@Composable
fun ToDoOfflineFirstTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    dynamicColor: Boolean = true,
    content: @Composable () -> Unit
) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }
        darkTheme -> DarkColorScheme
        else -> LightColorScheme
    }
    MaterialTheme(colorScheme = colorScheme, typography = Typography, content = content)
}

Lo que se ve es que al principio era `SettingsDatasource` y después aparece `SettingsDataSource` en el `AppModule` y en el árbol. Puede que lo renombrara, o puede ser un error de lectura.

- **Valor de `WhileSubscribed`:** en `img178` se lee `5_000L`, y en `img199` queda ilegible.
- **`Routes`** es una `abstract class` con `route: String`, no una `sealed class` como en la ToDoApp que se explicó antes en clase. Se lee igual en muchas capturas, así que parece seguro.
- **Tema y modo oscuro:** no se ve que el `darkMode` guardado llegue a `ToDoOfflineFirstTheme`. Lo lógico sería leerlo en `MainActivity` y pasarlo como `darkTheme`, pero las capturas terminan antes. Sin confirmar.
