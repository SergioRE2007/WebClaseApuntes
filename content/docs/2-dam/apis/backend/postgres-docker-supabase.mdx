La API guarda los datos en **PostgreSQL**. En clase se ve de dos formas: en local, dentro de un contenedor de Docker que se levanta con `docker-compose.yml` (20/10), y en la nube, con **Supabase** (03/11). Prisma se conecta a cualquiera de las dos con la misma variable, `DATABASE_URL`.

## PostgreSQL en un contenedor

<Concepto termino="Docker" definicion="Ejecuta programas en contenedores: un Postgres, la API… sin instalarlos en el ordenador. Docker Compose arranca varios a la vez a partir de un fichero docker-compose.yml.">Docker</Concepto> permite tener un PostgreSQL funcionando sin instalarlo en el ordenador: se descarga la imagen oficial y se arranca en un contenedor. Todo lo que hace falta se describe en un fichero, `docker-compose.yml`, que va en el repositorio. Así todo el equipo tiene la misma base de datos con la misma configuración.

El de desarrollo de la referencia **solo levanta Postgres**: la API se arranca aparte con `npm run dev`.

<Recorrido

    La versión del formato de Compose. Hoy esta clave está obsoleta (Compose la ignora), pero es lo que hay en el proyecto.
  </Paso>
  <Paso lineas="3-6" titulo="Un servicio llamado postgres">
    Usa la imagen oficial `postgres:16` y le pone nombre al contenedor para reconocerlo en Docker Desktop.
  </Paso>
  <Paso lineas="7-10" titulo="Variables de la imagen">

## La cadena de conexión

Prisma no recibe el usuario, la contraseña y el host por separado: lo recibe todo junto en **`DATABASE_URL`**, en el `.env`.

```bash title=".env"
DATABASE_URL="postgresql://postgres:<contraseña>@localhost:5432/app_db"
```

| Trozo | Qué es | En el compose de desarrollo |
| --- | --- | --- |
| `postgresql://` | El protocolo | — |
| `postgres` | Usuario | `POSTGRES_USER` |
| `<contraseña>` | Contraseña | `POSTGRES_PASSWORD` |
| `localhost` | Host | El ordenador, por el puerto publicado |
| `5432` | Puerto | `ports: "5432:5432"` |
| `app_db` | Base de datos | `POSTGRES_DB` |

Cuando la API también corre en Docker (el compose de producción), el host ya no es `localhost` sino **el nombre del servicio**: `postgresql://postgres:postgres@db:5432/app_db`. Lo verás en [Docker y Swagger](/docs/2-dam/apis/backend/docker-swagger).

## Supabase

**Supabase** es un PostgreSQL en la nube con un panel web. El 03/11 la API del profesor no usaba el Postgres de Docker sino uno de Supabase: solo cambia la `DATABASE_URL` del `.env`.

<DeClase fecha="03/11" proyecto="node-server-26-27" />

- La conexión va por el **pooler**, en `aws-1-eu-west-1.pooler.supabase.com:5432`. Un <Concepto termino="Pooler" definicion="Intermediario que reparte unas pocas conexiones a la base de datos entre muchas peticiones. Supabase tiene uno delante de cada base.">pooler</Concepto> reparte pocas conexiones a la base entre muchos clientes.
- En el panel **Connect to your project** se elige **Session pooler** con tipo URI, el recomendado para redes IPv4. De ahí se copia la cadena.
- El diálogo **Reset database password** avisa de que la contraseña es la misma para todas las formas de conexión.
- El profesor duplicó el `.env` como **`.env_local`**, un archivo sin seguimiento de Git. Las credenciales **nunca** se suben al repositorio (ni se ven en estos apuntes).

Lo que se usó del panel:

| Herramienta | Para qué |
| --- | --- |
| **Schema Visualizer** | Ver las tablas y sus relaciones como diagrama. Salían `_prisma_migrations`, `Media` y `User`, con la relación `Media.userId → User.id` (1:N). |
| **SQL Editor** | Escribir consultas SQL a mano. |
| **Table Editor** | Ver y editar las filas de una tabla como en una hoja de cálculo. También deja renombrar tablas, que es como se provocó el *drift* ([Prisma](/docs/2-dam/apis/backend/prisma)). |

Al renombrar una tabla desde el panel, Supabase avisó de que **no tenía RLS activado** y quedaba con acceso anónimo. RLS (*Row Level Security*) son las reglas de quién puede leer cada fila cuando se entra por la API de Supabase; la API de Express se conecta directamente a Postgres y no la usa.

## Mayúsculas y comillas en PostgreSQL

Esto pilló a todo el mundo en el SQL Editor. PostgreSQL **pasa a minúsculas los nombres que no van entre comillas dobles**. Prisma crea las tablas con el nombre del modelo tal cual y entre comillas (`"User"`, `"Media"`), así que:

<Terminal titulo="SQL Editor de Supabase">
{`sql> select * from media;
ERROR: 42P01: relation "media" does not exist
sql> select * from Media;
ERROR: 42P01: relation "media" does not exist
sql> select * from "Media";
(0 filas)`}
</Terminal>

- `Media` sin comillas se convierte en `media`, que no existe.
- `"Media"` con comillas respeta la mayúscula y la encuentra.
- Con `user` es aún más raro: `select * from user` sin comillas **no da error**, devuelve el usuario de la sesión (`postgres`). `user` es una palabra reservada de SQL. La tabla se consulta con `select * from "User"`.

<CompletarCodigo
  titulo="Consultas en el SQL Editor"
  enunciado="Completa las consultas para que encuentren las tablas que crea Prisma."
  lenguaje="sql"
  codigo={`select * from [["Media"]];
select * from [["User"]] where id = 1;
select * from [[_prisma_migrations]];`}
/>

`_prisma_migrations` va en minúsculas y sin comillas porque Prisma la crea así. Es la tabla donde apunta las migraciones aplicadas: `migration_name`, `checksum`, `started_at`, `finished_at` y `applied_steps_count`. El 03/11 tenía 2 filas, una por migración. Se explica en [Prisma 6](/docs/2-dam/apis/backend/prisma).

## Errores típicos <NoDadoEnClase inline />

No salieron en clase, pero son los primeros con los que te vas a encontrar:

- **`P1001: Can't reach database server`**: Postgres no está arrancado (abre Docker Desktop y levanta el contenedor) o la `DATABASE_URL` tiene mal el puerto o la contraseña.
- **Con Supabase, `migrate` se queda colgado**: pasa si usas el *Transaction pooler* (puerto 6543), que no admite migraciones. Usa el *Session pooler* o la conexión directa (puerto 5432), como en clase. Si necesitas el de 6543 para la app, en Prisma 6 se añade `directUrl = env("DIRECT_URL")` en el `datasource` con la conexión de 5432 para las migraciones, y `?pgbouncer=true` al final de la `DATABASE_URL`.
