- **`[versions]`, `[libraries]` y `[plugins]`**: el catálogo pone cada versión en un solo sitio. En los `build.gradle.kts` se usa como `libs.hilt.android` (los guiones pasan a puntos).
- **`apply false` en la raíz**: declara el plugin y su versión para todo el proyecto, pero no lo aplica ahí. Se aplica en `app`.
- **`ksp(...)` frente a `implementation(...)`**: `ksp` es para los **compiladores** (Room y Hilt), que generan código al compilar y no van dentro de la app. `implementation` es para lo que sí usa la app al ejecutarse.
- **El plugin de Hilt sin la dependencia `hilt-android` hace fallar el sync.** Van siempre juntos.
- Salieron errores de `compileSdk` (`checkDebugAarMetadata`) y se pasó a `compileSdk release(37)`, con la sintaxis de AGP 9 `release(37) { minorApiLevel = 1 }`, `minSdk 35` y `targetSdk 37`.
- La versión de Kotlin se lee como <Dudoso nota="También se lee `2.3.10`.">`2.2.10`</Dudoso>. El código de este bloque se ha compilado con **Kotlin 2.4**.

## Lo que hay que añadir <NoDadoEnClase inline />

<NoDadoEnClase>
  Estas dependencias no se añadieron en clase (o no se vio la versión). Son las que necesita el código de este bloque, compilado con las versiones de clase.
</NoDadoEnClase>

Esto va en `app/build.gradle.kts`, además de lo de clase:

```kotlin title="app/build.gradle.kts"
implementation("com.squareup.retrofit2:retrofit:3.0.0")
implementation("com.squareup.retrofit2:converter-gson:3.0.0")
implementation("com.squareup.okhttp3:logging-interceptor:4.12.0")
implementation("androidx.room3:room3-runtime:3.0.3")
ksp("androidx.room3:room3-compiler:3.0.3")
implementation("androidx.datastore:datastore-preferences:1.3.0")
implementation("androidx.compose.material:material-icons-core")
```

| Dependencia | Para qué | Página |
| --- | --- | --- |
| `retrofit` y `converter-gson` | Llamar a tu API y convertir el JSON | [CRUD con Retrofit](/docs/2-dam/kotlin/para-el-proyecto/crud-con-retrofit) |
| `logging-interceptor` | Ver las peticiones en el Logcat | [Conectar con tu API](/docs/2-dam/kotlin/para-el-proyecto/conectar-con-tu-api) |
| `room3-runtime` y `room3-compiler` | Room 3 (el compilador, con `ksp`) | [Room con relaciones](/docs/2-dam/kotlin/para-el-proyecto/room-relaciones) |
| `datastore-preferences` | DataStore | [DataStore](/docs/2-dam/kotlin/para-el-proyecto/datastore) |
| `material-icons-core` | `Icons.Default.Home`, `Settings`, `ShoppingCart`… | [Navegación del proyecto](/docs/2-dam/kotlin/para-el-proyecto/navegacion-del-proyecto) |

- `logging-interceptor` va en la versión **4.12.0** porque es la de OkHttp que trae Retrofit 3.0.0. Si mezclas versiones de OkHttp, puede fallar al arrancar.
- `material-icons-core` **no lleva versión** porque la pone el BOM de Compose (el `implementation(platform(libs.androidx.compose.bom))` que ya trae la plantilla). Trae los iconos básicos (`Home`, `Settings`, `ShoppingCart`, `Add`…). Para todos los iconos, `material-icons-extended`, que pesa bastante más.
- Para usar `BuildConfig.BASE_URL` hace falta además `buildConfig = true` en `buildFeatures`.

### Mejor en el catálogo

Es mejor pasarlo a `libs.versions.toml`, como en clase el 13/11. Así quedaría:

```toml title="gradle/libs.versions.toml"
[versions]
retrofit = "3.0.0"
okhttp = "4.12.0"
room3 = "3.0.3"
datastore = "1.3.0"

[libraries]
retrofit = { group = "com.squareup.retrofit2", name = "retrofit", version.ref = "retrofit" }
converter-gson = { group = "com.squareup.retrofit2", name = "converter-gson", version.ref = "retrofit" }
logging-interceptor = { group = "com.squareup.okhttp3", name = "logging-interceptor", version.ref = "okhttp" }
androidx-room3-runtime = { group = "androidx.room3", name = "room3-runtime", version.ref = "room3" }
androidx-room3-compiler = { group = "androidx.room3", name = "room3-compiler", version.ref = "room3" }
androidx-datastore-preferences = { group = "androidx.datastore", name = "datastore-preferences", version.ref = "datastore" }
androidx-material-icons-core = { group = "androidx.compose.material", name = "material-icons-core" }
```

```kotlin title="app/build.gradle.kts"
dependencies {
    implementation(libs.retrofit)
    implementation(libs.converter.gson)
    implementation(libs.logging.interceptor)
    implementation(libs.androidx.room3.runtime)
    ksp(libs.androidx.room3.compiler)
    implementation(libs.androidx.datastore.preferences)
    implementation(libs.androidx.material.icons.core)
}
```

`group` y `name` es otra forma de escribir el `module = "grupo:nombre"` de clase; las dos valen. Si ya tenías Retrofit o Room puestos con texto (`"androidx.room3:room3-runtime:3.0.3"`), quita esas líneas al pasar al catálogo para no tenerlas dos veces.

<Callout type="warn" title="minSdk 35">
  En clase se puso `minSdk 35`, que solo instala en Android 15 o más. Si tu móvil es más viejo, sale `INSTALL_FAILED_OLDER_SDK`. Bájalo (por ejemplo, a 26, que ya trae `java.time` para `LocalDate`) y vuelve a compilar: si alguna librería pide un `minSdk` mayor, Gradle te lo dice al compilar.
</Callout>

## Ejercicios

<Ejercicio titulo="Pasa tus dependencias al catálogo" dificultad="facil">
  Mira tu `app/build.gradle.kts` y pasa al catálogo todas las dependencias que estén escritas como texto (`"grupo:nombre:versión"`). Sincroniza y compila.

  <Pista>Android Studio lo hace solo: pon el cursor sobre la línea, Alt+Intro y "Replace with new library catalog declaration".</Pista>

  <Solucion>

  Por cada línea con texto, una entrada en `[libraries]` (y su versión en `[versions]` si la comparte con otra) y, en `build.gradle.kts`, el acceso con puntos. Por ejemplo, `implementation("androidx.datastore:datastore-preferences:1.3.0")` pasa a `implementation(libs.androidx.datastore.preferences)` con la entrada `androidx-datastore-preferences` del catálogo de esta página. Si compila igual que antes, está bien.

  </Solucion>
</Ejercicio>
