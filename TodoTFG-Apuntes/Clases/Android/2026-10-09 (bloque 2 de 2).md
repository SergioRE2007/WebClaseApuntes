## 2. Conceptos y patrones

- **Rutas tipadas con argumentos.** Si un destino lleva datos, su ruta es una clase con propiedades, como `TaskDetail(val id: Int)`. Si no lleva datos, es un `object`. Para navegar se usa `controller.navigate(Route.TaskDetail(id = id))`.
- **Leer el argumento en el destino.** En `composable<Route.TaskDetail> { backStackEntry -> ... }` se llama a `backStackEntry.toRoute()`. Si no se escribe el tipo, hay que dárselo: con `toRoute<Route.TaskDetail>()` o poniéndolo en la variable. La documentación también menciona `SavedStateHandle.toRoute()`, que es la forma de leerlo dentro del ViewModel.
- **Las pantallas no conocen el `navController`.** Reciben callbacks (`toCreate: () -> Unit` y `toDetail: (Int) -> Unit`) y el NavHost los conecta con `navigate`.
- **El callback baja por los composables.** El NavHost se lo da a `TaskListScreen` como `(Int) -> Unit`. La pantalla se lo da a `TaskCard` como `() -> Unit`, envolviéndolo en `{ toDetail(it.id) }`, donde `it` es la tarea del `items`. Así la tarjeta no necesita saber su id ni a qué pantalla se va.
- **Tipos función de Kotlin.** `() -> Unit` y `(Int) -> Unit`, y lambdas con parámetro con nombre (`{ id -> ... }`).
- **`Modifier.clickable`.** `onClick` es obligatorio. Tiene dos versiones: una con `interactionSource` e `indication` y otra sin ellos. `Card` sola no responde a toques (lo dice su documentación).
- **`Switch(checked = ..., onCheckedChange = null)`.** Con `null` el Switch es de solo lectura.
- **Hilt.**
  - El módulo es una clase abstracta con `@Module @InstallIn(SingletonComponent::class)`.
  - `@Binds @Singleton` ata la interfaz con su implementación.
  - El ViewModel lleva `@HiltViewModel` y `@Inject constructor(private val _repository: TaskRepository)`.
  - En la pantalla, `viewModel: TaskListViewModel = hiltViewModel()`.
- **`hiltViewModel()` frente a `viewModel()`.** Con Hilt y Navigation hay que usar `hiltViewModel()`. Devuelve el ViewModel ligado al `ViewModelStoreOwner` actual, que en Navigation es la entrada de la pila.
- **El ViewModel es la fuente de datos de la pantalla.** El repositorio sale de los parámetros de la pantalla y pasa al constructor del ViewModel, que tiene `readAll()`. Siguen dos TODO: `// TODO COMO HAGO ESTO QUE SEA OBSERVABLE?` (se resuelve más adelante con StateFlow) y `create()` vacía.
- **Convención `_nombre`** para la propiedad privada (`_repository`).

## 3. Código del profesor (reconstruido)

### `ui/navigation/ToDoNavHost.kt`
```kotlin
@Composable
fun ToDoNavHost() {
    val controller = rememberNavController()

    NavHost(
        navController = controller,
        startDestination = Route.TaskList
    ) {
        composable<Route.TaskList> {
            TaskListScreen(
                toCreate = {
                    controller.navigate(Route.TaskCreate)
                },
                toDetail = { id ->
                    controller.navigate(Route.TaskDetail(id = id))
                }
            )
        }

        composable<Route.TaskCreate> {
            TaskCreateScreen()
        }

        composable<Route.TaskDetail> { backStackEntry ->
            val detail: Route.TaskDetail = backStackEntry.toRoute()
            TaskDetailScreen(id = detail.id)
        }
    }
}
```
