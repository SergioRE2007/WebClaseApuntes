## Componentes interactivos de DAM Apuntes

### Quiz (test)

Un test que se responde pregunta a pregunta, con corrección inmediata, explicación, puntuación final, botón de reintentar y opción de revisar todas las respuestas al terminar. Hay tres tipos de pregunta:

- **Opciones** (por defecto): hijos `<Opcion>`, marca la buena con `correcta`. Si marcas **más de una** correcta, la pregunta pasa a ser de respuesta múltiple automáticamente (casillas + botón Comprobar).
- **Verdadero/falso**: `tipo="vf"` y `respuesta={true}` o `respuesta={false}`.
- **Texto**: `tipo="texto"` y `respuesta="..."` (o una lista de respuestas válidas). Ideal para "¿qué imprime este código?".

<Quiz titulo="Quiz de ejemplo" descripcion="Así lo verá el alumnado">

    <Opcion>`class`</Opcion>
    <Opcion correcta>`new`</Opcion>
    <Opcion>`this`</Opcion>
  </Pregunta>
  <Pregunta enunciado="¿Cuáles son tipos primitivos?" explicacion="`String` es una clase, no un tipo primitivo.">
    <Opcion correcta>`int`</Opcion>
    <Opcion correcta>`boolean`</Opcion>
    <Opcion>`String`</Opcion>
  </Pregunta>
  <Pregunta tipo="vf" enunciado="`main` tiene que ser `static`." respuesta={true} explicacion="La JVM lo llama sin crear ningún objeto." />
  <Pregunta tipo="texto" enunciado="¿Qué imprime `System.out.println(7 / 2);`?" respuesta="3" explicacion="Dividir dos `int` da un `int`: se descarta la parte decimal." />
</Quiz>

## Marcas del material de clase

El material de 2º sale de capturas de los vídeos de clase. Hay que **separar siempre lo que se dio en clase de lo que no**, que se vean las lecturas dudosas y que no se rellene el código que no se llegó a ver. Estas cuatro marcas sirven para eso. El buscador y el Tutor DAM también las tienen en cuenta.

### NoDadoEnClase

### Comparar y Lado

Compara **la forma de clase con la buena** (las "prácticas raras" del código de clase) o dos alternativas. Con `columnas`, en pantallas anchas se ven los dos lados a la vez y en móvil sigue el conmutador: úsalo solo con código corto.

<Comparar titulo="Proveer la base de datos con Hilt">

@Provides
fun providesDatabase(@ApplicationContext context: Context): PokemonDatabase {
    val db = Room.databaseBuilder<PokemonDatabase>(
        context = context,
        name = "pokemon_db"

    return db

Sin `@Singleton`, Hilt crea una base de datos nueva cada vez que alguien la pide.

### Recorrido y Paso (código paso a paso)

Explica un trozo de código **paso a paso**: cada `<Paso>` ilumina unas líneas y muestra su explicación. Se avanza con Anterior/Siguiente, con las flechas ← → del teclado o pulsando un paso de la lista. El código se resalta con los mismos colores que los bloques normales.

<Recorrido
  titulo="TaskListViewModel.kt"
  lenguaje="kotlin"
  codigo={`@HiltViewModel
class TaskListViewModel @Inject constructor(
    private val _repository: TaskRepository
) : ViewModel() {
    private val _state = MutableStateFlow<TaskListScreenState>(TaskListScreenState.Loading)
    val state: StateFlow<TaskListScreenState>
        get() = _state.asStateFlow()

    init { load() }

    fun load() {
        viewModelScope.launch {
            _state.value = TaskListScreenState.Loading
            val tasks = _repository.readAll()
            _state.value = TaskListScreenState.Success(tasks)
        }
    }
}`}
>
  <Paso lineas="1-4" titulo="Hilt crea el ViewModel">
    `@HiltViewModel` y `@Inject constructor` le dicen a Hilt que construya el ViewModel y le pase el `TaskRepository` que tiene registrado.
  </Paso>
  <Paso lineas="5-7" titulo="Backing property">
    `_state` es mutable y privado; fuera solo se ve `state`, de solo lectura. Así la pantalla no puede cambiar el estado.
  </Paso>
  <Paso lineas="9" titulo="Carga al crearse">
    El bloque `init` llama a `load()` en cuanto se crea el ViewModel.
  </Paso>
  <Paso lineas="12" titulo="Una corrutina ligada al ViewModel">
    `viewModelScope.launch` lanza una corrutina que se cancela sola cuando el ViewModel se destruye.
  </Paso>
  <Paso lineas="13-15" titulo="De Loading a Success">
    Primero publica `Loading`, espera a `readAll()` (que es `suspend`) y publica `Success` con las tareas. La pantalla recompone en cada cambio.
  </Paso>
</Recorrido>

## Demos a medida (con import)

Cuando ningún componente del catálogo sirve (una pantalla de Compose simulada, un formulario de Angular que valida en vivo…), puedes escribir una **demo a medida** en React e importarla solo en el tema que la usa. Esta es una demo de ejemplo importada en esta misma página:

<DemoEstado />

<Steps>
  <Step>

#### Crea el componente

  En `components/temas/<grupo>/<nombre>.tsx`, donde el grupo es el módulo (`kotlin`, `acceso-a-datos`, `apis`…). Si usa estado o eventos, empieza por `'use client'`. Exporta una función con nombre en PascalCase.

  </Step>
  <Step>

#### Usa el estilo de la web

  Reutiliza `bloque`, `cabecera`, `etiqueta`, `botonPrimario`, `botonSecundario`… de `@/components/interactive/estilos` y los colores `fd-*`. Nada de degradados, sombras de color ni emojis.

  </Step>
  <Step>

#### Impórtalo en el MDX

  Justo debajo del frontmatter, con una línea en blanco después. Las props que le pases tienen que ser datos simples (textos, números, listas), no funciones.

  </Step>
</Steps>

```tsx title="components/temas/guia-autor/demo-estado.tsx"
'use client';

import { useState } from 'react';
import { bloque, botonSecundario, cabecera, etiqueta } from '@/components/interactive/estilos';

export function DemoEstado({ inicial = 0 }: { inicial?: number }) {
  const [valor, setValor] = useState(inicial);
  return (
    <section className={bloque}>
      <div className={cabecera}>
        <span className={etiqueta}>Demo</span>
      </div>
      <button type="button" onClick={() => setValor(valor + 1)} className={botonSecundario}>
        {valor}
      </button>
    </section>
  );
}
```
