## JSON Server: una API REST falsa

Para programar el cliente Angular antes de tener una API de verdad, la actividad usa **JSON Server**: lee un fichero `db.json` y crea una API REST completa a partir de él. **Cada clave de primer nivel es un recurso**: si el JSON tiene `"games": [...]`, tienes `/games` y `/games/:id`.

<DeClase fecha="28/10, 05/11" proyecto="proj-game" />

El documento de la actividad pide expresamente la **versión clásica**, la 0.17.4 (la 1.x funciona distinto):

<Terminal titulo="WSL Ubuntu">
{`$ npm install --save-dev json-server@0.17.4
npm warn deprecated connect-pause@0.1.1
30 vulnerabilities (2 low, 12 moderate, 14 high, 2 critical)
$ npx json-server --watch db.json --port 3000`}
</Terminal>

<Callout type="warn" title="npm audit fix --force, no a ciegas">
  npm sugiere `npm audit fix --force` para las vulnerabilidades. La opción `--force` puede actualizar paquetes a versiones incompatibles (por ejemplo, saltar a otra versión de JSON Server) y romper el proyecto.
</Callout>

### Lo que ofrece JSON Server

| Petición | Qué hace |
| --- | --- |
| `GET /games` | Lista todos los juegos |
| `GET /games/3` | El juego con `id` 3 (404 si no existe) |
| `POST /games` | Crea un juego; JSON Server le pone el `id` |
| `PUT /games/3` | Sustituye el juego 3 entero |
| `DELETE /games/3` | Borra el juego 3 |
| `GET /games?_page=2&_limit=5` | La página 2, de 5 en 5 |

- `--watch` recarga la API cuando cambia `db.json`, y los `POST`/`PUT` se guardan en ese mismo fichero.
- `--port 3000`: la API va en el 3000 y Angular en el 4200.
- Escribiendo `s` y pulsando Intro en la terminal de JSON Server se guarda una copia (*snapshot*) de la base.
- `GET /` devuelve 404; `GET /games` devuelve 200 (o 304 si el navegador ya lo tiene en caché, como salió el 05/11).

Escribir `json-server ...` a secas en la terminal da `command not found`: los programas instalados en el proyecto están en `node_modules/.bin`, que no está en el `PATH`. Se arranca con `npx` o con un script de `package.json`, que sí los encuentra.

## El modelo Game

<DeClase fecha="05/11" proyecto="proj-game" />

```ts title="src/app/models/game.ts"
export interface Game {
  id?: number;
  title: string;
  genre: string;
  platform: string;
  price: number;
  stock: number;
}
```

- Es una `interface` de TypeScript: solo existe al compilar, como una interfaz de Java sin métodos. Sirve para que el editor te avise si escribes mal una propiedad.
- El 05/11 se añadió `stock`, que el modelo del proyecto no tenía y el de la guía sí.
- `id?` es **opcional**: su tipo pasa a ser `number | undefined`. Al crear un juego todavía no tienes `id` (lo pone JSON Server), así que el mismo modelo vale para crear y para leer.

<Callout title="Otra forma que salió el 27/10">
  En `angular-http` el modelo tenía `id` obligatorio y un segundo tipo para crear: `type NewPost = Omit<Post, 'id'>`. Son las dos formas de resolver lo mismo: un modelo con `id?` o dos tipos.
</Callout>

## GameService

<DeClase fecha="12/11" proyecto="proj-game" />

El servicio está en `services/game.service.ts`. Los servicios de las clases anteriores se generaron con `ng g s services/...` y llevan `@Injectable({ providedIn: 'root' })`, que hace que haya una sola instancia para toda la app (un *singleton*). De `GameService` solo se ven los métodos:

<Recorrido
  titulo="src/app/services/game.service.ts (fragmento)"
  lenguaje="typescript"
  codigo={`getGameById(id: number): Observable<Game> {
  return this.http.get<Game>(\`\${this.apiUrl}/\${id}\`);
}

getGamesPyPage(pag: number, tamPage: number) {
  return this.http.get<Game[]>(this.apiUrl + \`?_page=\${pag}&_limit=\${tamPage}\`, {
    observe: 'response'
  });
}

create(game: Game) {
  return this.http.post<Game>(this.apiUrl, game);
}

update(game: Game) {
  if (game.id) {
    return this.http.put<Game>(this.apiUrl + \`/\${game.id}\`, game);
  }
  throw new Error(\`Game a actualizar sin id = \${game}\`);
}`}
>
  <Paso lineas="1-3" titulo="Un juego por id">
    `get<Game>` tipa la respuesta: devuelve un `Observable<Game>`. Sin el genérico, `HttpClient` devuelve `Observable<Object>` y pierdes el autocompletado. La URL se monta con una plantilla de texto (comillas invertidas y `${}`).
  </Paso>
  <Paso lineas="5-9" titulo="Una página de juegos">
    Añade `?_page=` y `&_limit=` a la URL: la paginación la hace JSON Server. Con `observe: 'response'` no devuelve solo el array, sino la **respuesta completa** (`HttpResponse<Game[]>`), con el estado, las cabeceras y el cuerpo.
  </Paso>
  <Paso lineas="11-13" titulo="Crear (POST)">
    Manda el juego sin `id` y JSON Server responde con el juego creado, ya con su `id`.
  </Paso>
  <Paso lineas="15-20" titulo="Actualizar (PUT)">
    Si el juego trae `id`, hace `PUT /games/:id`. Si no, lanza un `Error`: actualizar algo que no existe no tiene sentido.
  </Paso>
</Recorrido>

Detalles del código de clase:

- `getGamesPyPage` es una errata del código de clase (quería decir *ByPage*). Si copias el código, puedes llamarlo `getGamesByPage`, pero en los apuntes se deja como estaba.
- El final de la URL de `getGamesPyPage` sale cortado en las capturas: se lee <Dudoso nota="Se ve tamPag… y se supone que es la variable tamPage.">`&_limit=${tamPage}`</Dudoso>.
- La ruta del import sale como `../services/game.service` en unas capturas y como `games.service` en otra.
- `update` recibe el `Game` entero y saca el `id` de dentro. Por eso en el formulario reactivo (18/11) se le pasa `{ id: this.editGame()?.id, ...form.value }`.

<NoSeVio titulo="El principio de GameService">
  No se ven el `import`, el `@Injectable`, cómo se inyecta `HttpClient` ni el valor de `apiUrl`. Por el error de CORS del 18/11 se sabe que las peticiones iban a `http://localhost:3000/games`. El patrón de clase en otros servicios (27/10 y 28/10) es `private http = inject(HttpClient)` y `private apiUrl = '...'` dentro del servicio.
</NoSeVio>

## Paginación con _page y _limit

<DeClase fecha="05/11, 12/11" proyecto="proj-game" nota="el listado paginado ya estaba hecho al empezar el 05/11" />

La paginación se hace **en el servidor**: Angular pide una página concreta y JSON Server devuelve solo esos juegos. Además, cuando se pagina, JSON Server 0.17 añade la cabecera `X-Total-Count` con el número total de juegos. Para leer esa cabecera hace falta `observe: 'response'`; sin él, el `subscribe` solo recibe el array y no hay forma de saber cuántas páginas hay. En clase no llega a verse el código que lee la cabecera (más abajo tienes una forma de escribirlo, marcada como no dada), pero `observe: 'response'` está ahí para eso.

Prueba el simulador: cambia el tamaño, avanza páginas y quita `observe: 'response'` para ver qué se pierde. Con 19 juegos y 5 por página salen 4 páginas (`Math.ceil(19 / 5)`), y con 10 por página, 2: es lo que se vio en el navegador el 05/11 ("1 de 4" y "2 de 2").

<SimuladorPaginacion />

Fíjate también en la segunda casilla: si estás en la página 4 de 5 en 5 y cambias a 10 por página sin volver a la 1, pides la página 4 de 2, que viene vacía.

### La plantilla del padre (de clase)

```html title="src/app/app.component.html"
<span>Buscar por ID: </span>
<input type="string" #buscarId />
<button (click)="onBuscarId(buscarId.value)">Buscar</button>

@for (game of this.games; track game.id) {
  {{ game | json }}
  <button type="button" (click)="this.editGame = game">Editar</button><br/>
}

<select #tamPage (change)="onChangeTamPage(tamPage.value)">
  <option value="5">5</option>
  <option value="10">10</option>
</select>
<div>{{ this.pag }} de {{ this.totalPag }}</div>
<button [disabled]="this.pag === 1" (click)="onAntPag()">Anterior</button>
<button [disabled]="this.pag === this.totalPag" (click)="onSigPag()">Siguiente</button>

<h1>CRUD</h1>
<app-crud [editGame]="this.editGame" (actualizaGames)="onActualizaGames($event)"></app-crud>
```

- `#buscarId` y `#tamPage` son **referencias de plantilla**: dan acceso al elemento HTML, y `tamPage.value` es el valor del `select` (un `string`, aunque ponga "5").
- `(click)` y `(change)` son *event binding*; `[disabled]` es *property binding*: desactiva Anterior en la página 1 y Siguiente en la última.
- `@for (...; track game.id)`: el `track` es obligatorio y le dice a Angular cómo reconocer cada elemento al repintar.
- `game | json` pinta el objeto entero mientras se depura. En un componente *standalone* hay que importar `JsonPipe`.
- El buscador lleva `type="string"`, que no es un tipo válido de HTML (el navegador lo trata como `text`). Está así en el código de clase.
- El `$event` de `(actualizaGames)` es una suposición: el argumento sale cortado en las capturas <Dudoso />.

Y la cabecera de la clase, que es lo único que se ve del `.ts`:

```ts title="src/app/app.component.ts (cabecera, 05/11)"

  imports: [RouterOutlet, JsonPipe, CrudComponent],

  title = 'proj-game';

  tamanoPagina = 5;
  totalCount = 0;
  totalPag = 0;
```

Aquí el servicio se inyecta **por constructor** (`private` es imprescindible: sin él, `gameService` no es una propiedad y sale el error TS2339), mientras que en `CrudComponent` se usa `inject()`, la forma moderna. Las dos funcionan igual. Más adelante se añade la propiedad `editGame?: Game` para el botón Editar.

### Una forma de escribir esos métodos <NoDadoEnClase inline />

<NoDadoEnClase>
  Esto no se vio en clase: es una forma estándar de completar los métodos que no salen en las capturas, con los mismos nombres que usa la plantilla. Si te preguntan, di que lo has escrito tú.
</NoDadoEnClase>

```ts title="src/app/app.component.ts (métodos)"
loadGames(): void {
  this.gameService.getGamesPyPage(this.pag, this.tamanoPagina).subscribe(resp => {
    this.games = resp.body ?? [];
    this.totalCount = Number(resp.headers.get('X-Total-Count') ?? 0);
    this.totalPag = Math.ceil(this.totalCount / this.tamanoPagina);
  });
}

onChangeTamPage(valor: string): void {
  this.tamanoPagina = Number(valor);
  this.pag = 1;
  this.loadGames();
}

onAntPag(): void {
  if (this.pag > 1) {
    this.pag--;
    this.loadGames();
  }
}

onSigPag(): void {
  if (this.pag < this.totalPag) {
    this.pag++;
    this.loadGames();
  }
}

onBuscarId(valor: string): void {
  const id = Number(valor);
  if (!id) {
    this.loadGames();
    return;
  }
  this.gameService.getGameById(id).subscribe(game => this.games = [game]);
}

onActualizaGames(game: Game): void {
  console.log('Guardado', game);
  this.editGame = undefined;
  this.loadGames();
}
```

- `resp.body` es `Game[] | null`, de ahí el `?? []`.
- `resp.headers.get(...)` devuelve un `string` (o `null`): hay que convertirlo con `Number`.
- Al cambiar el tamaño se vuelve a la página 1, por lo que has visto en el simulador.
- `onActualizaGames` vacía `editGame` después de guardar, para que el padre no siga apuntando a un juego que ya se ha guardado. Ten en cuenta que el hijo solo se entera (`ngOnChanges`) cuando la entrada cambia de **referencia**: si pulsas Editar dos veces en el mismo objeto de la lista, la segunda vez no pasa nada. Aquí no molesta, porque `loadGames()` trae objetos nuevos.

### Otros parámetros de JSON Server <NoDadoEnClase inline />

JSON Server 0.17 también filtra y ordena desde la URL. En clase solo se usaron `_page` y `_limit`, pero te sirven para practicar el requisito de búsqueda y orden antes de tener tu API:

| URL | Qué devuelve |
| --- | --- |
| `/games?genre=RPG` | Los juegos cuyo `genre` es exactamente "RPG" |
| `/games?title_like=runner` | Los que tienen "runner" en el título (expresión regular, sin distinguir mayúsculas) |
| `/games?q=space` | Búsqueda de texto en todos los campos |
| `/games?_sort=price&_order=desc` | Ordenados por precio, de mayor a menor |
| `/games?_sort=price&_order=asc&_page=1&_limit=5` | Se combinan con la paginación |

En tu proyecto, la búsqueda y la paginación las tiene que hacer tu API con Prisma: lo tienes en [Listado con filtros, paginación y token](/docs/2-dam/acceso-a-datos/angular-avanzado/listado-filtros-y-token).

  <Tarjeta frente="¿Por qué `json-server` a secas da `command not found`?">Porque está instalado en el proyecto (`node_modules/.bin`), no en el sistema. Se usa `npx` o un script de npm.</Tarjeta>

<Ejercicio titulo="Completa el listado paginado" dificultad="media">
  Con la plantilla de clase de `app.component.html` y el `GameService` de arriba, escribe en `AppComponent` los métodos `loadGames()`, `onAntPag()` y `onSigPag()` para que funcionen los botones y el texto "X de Y".

  <Pista>`getGamesPyPage` devuelve una `HttpResponse`: los juegos están en `resp.body` y el total en la cabecera `X-Total-Count`.</Pista>
  <Pista>El total de páginas es `Math.ceil(total / tamanoPagina)`. Las cabeceras llegan como texto.</Pista>

  <Solucion>

Esta solución no es de clase (los métodos no se ven en las capturas):

```ts
loadGames(): void {
  this.gameService.getGamesPyPage(this.pag, this.tamanoPagina).subscribe(resp => {
    this.games = resp.body ?? [];
    this.totalCount = Number(resp.headers.get('X-Total-Count') ?? 0);
    this.totalPag = Math.ceil(this.totalCount / this.tamanoPagina);
  });
}

onAntPag(): void {
  if (this.pag > 1) { this.pag--; this.loadGames(); }
}

onSigPag(): void {
  if (this.pag < this.totalPag) { this.pag++; this.loadGames(); }
}
```
