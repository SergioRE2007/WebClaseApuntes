Un componente hijo que siempre pinta lo mismo sirve de poco. Para que sea **reutilizable**, el padre tiene que poder darle datos y el hijo tiene que poder avisar al padre cuando pasa algo. Angular lo hace con dos funciones:

| Sentido | En el hijo | En la plantilla del padre |
| --- | --- | --- |
| Padre → hijo | `dato = input<T>()` | `[dato]="valor"` (property binding) |
| Hijo → padre | `aviso = output<T>()` y `this.aviso.emit(valor)` | `(aviso)="metodo($event)"` (event binding) |

<Callout type="idea" title="Lo que vas a aprender">
  - Declarar entradas con `input()` e `input.required()` y leerlas.
  - Emitir eventos propios con `output()` y recibirlos en el padre con `$event`.
  - Reaccionar a un cambio de entrada con `ngOnChanges`.
  - Reconocer la sintaxis antigua con `@Input()` y `@Output()`.
</Callout>

## Padre → hijo: `input()`

<Callout type="warn" title="Los ejemplos de la lámpara no son código de clase">
  En la lámpara de clase (14/10) el padre no le pasó nada al hijo y el hijo no llegó a mandar su estado: `estadoLampara` quedó declarada y sin usar. Los ejemplos de `input()` y `output()` con la lámpara de este apartado y del siguiente son una forma de terminarla, escrita para estos apuntes. Lo que sí se escribió en clase es el CRUD de videojuegos del 12/11, que tienes más abajo.
</Callout>

En el hijo se declara una propiedad con `input()`. El padre le da valor con un property binding usando **el mismo nombre**:

<Tabs items={['Hijo', 'Padre']}>
  <Tab value="Hijo">

```ts title="lampara.component.ts"
import { Component, input } from '@angular/core';

@Component({
  selector: 'app-lampara',
  templateUrl: './lampara.component.html'
})
export class LamparaComponent {
  enchufada = input(false);          // InputSignal<boolean>, por defecto false
}
```

```html title="lampara.component.html"
@if (enchufada()) {
  <p>Con corriente</p>
} @else {
  <p>Sin corriente</p>
}
```

  </Tab>
  <Tab value="Padre">

```html title="app.component.html"
<app-lampara [enchufada]="enchufado"></app-lampara>
```

Cada vez que cambia `enchufado` en el padre, al hijo le llega el valor nuevo.

  </Tab>
</Tabs>

- `input()` devuelve un **signal de solo lectura**: se lee **llamándolo**, `enchufada()`, también en la plantilla. El hijo no puede cambiarlo: el dato es del padre.
- El tipo se deduce del valor por defecto (`input(false)` es `boolean`) o se escribe: `input<Product>()`. Sin valor por defecto, el tipo incluye `undefined`.
- **`input.required<T>()`**: el padre está **obligado** a pasarlo. Si no lo hace, error de compilación. No lleva valor por defecto.

## Hijo → padre: `output()`

En el hijo se declara un `output()` y se llama a `.emit(valor)` cuando quieras avisar. En el padre se escucha como cualquier evento, y **`$event` es el valor emitido**:

<Tabs items={['Hijo', 'Padre']}>
  <Tab value="Hijo">

```ts title="lampara.component.ts"
import { Component, input, output } from '@angular/core';

@Component({
  selector: 'app-lampara',
  templateUrl: './lampara.component.html'
})
export class LamparaComponent {
  enchufada = input(false);
  estadoCambiado = output<boolean>();

  protected encendida = false;

  protected pulsar(): void {
    this.encendida = !this.encendida;
    this.estadoCambiado.emit(this.encendida);
  }
}
```

```html title="lampara.component.html"
<button (click)="pulsar()" [disabled]="!enchufada()">Interruptor</button>
```

  </Tab>
  <Tab value="Padre">

```html title="app.component.html"
<p>Último estado recibido: {{ estadoLampara ? 'ENCENDIDA' : 'APAGADA' }}</p>

<app-lampara
  [enchufada]="enchufado"
  (estadoCambiado)="estadoLampara = $event">
</app-lampara>
```

`$event` es el `boolean` que ha emitido el hijo.

  </Tab>
</Tabs>

## El caso de clase: el CRUD de videojuegos

<DeClase fecha="12/11" proyecto="proj-game" />

El 12/11 se usó para que el listado (el padre, `AppComponent`) le pase al formulario (el hijo, `CrudComponent`) el juego que hay que editar, y para que el formulario avise al padre cuando ha guardado. Recortado a lo que tiene que ver con la comunicación:

```ts title="crud.component.ts (recortado)"
import { Component, input, OnChanges, output, SimpleChanges } from '@angular/core';

export class CrudComponent implements OnChanges {
  edit = false;
  editGame = input.required<Game | undefined>();
  actualizaGames = output<Game>();
  game: Game = { title: '', genre: '', platform: '', price: 0, stock: 0 };

  ngOnChanges(changes: SimpleChanges): void {
    if (changes['editGame']?.currentValue) {
      this.game = { ...changes['editGame'].currentValue };
      this.edit = true;
    }
  }
}
```

```html title="app.component.html (padre, recortado)"
@for (game of this.games; track game.id) {
  {{ game | json }}
  <button type="button" (click)="this.editGame = game">Editar</button><br/>
}

<app-crud [editGame]="this.editGame" (actualizaGames)="onActualizaGames($event)"></app-crud>
```

- En la llamada `onActualizaGames($event)`, el <Dudoso nota="El resumen de clase dice que el `$event` es una suposición: no se lee bien en la captura.">`$event`</Dudoso> no se lee con seguridad.
- `input.required<Game | undefined>()`: el padre tiene que pasarlo siempre, aunque al principio sea `undefined` (todavía no se ha pulsado "Editar").
- Al guardar, el hijo hace `this.actualizaGames.emit(gameUpdated)` con el juego que devuelve la API.

## `ngOnChanges`: reaccionar a un cambio de entrada

<DeClase fecha="12/11" proyecto="proj-game" />

`ngOnChanges(changes: SimpleChanges)` se ejecuta cada vez que el padre cambia alguna entrada del hijo (y una vez antes de `ngOnInit`, si hay entradas enlazadas). `changes` es un objeto con una clave por cada entrada que ha cambiado:

| Expresión | Qué es |
| --- | --- |
| `changes['editGame']` | El cambio de esa entrada, o `undefined` si no ha cambiado. |
| `changes['editGame'].currentValue` | El valor nuevo. |
| `changes['editGame'].previousValue` | El valor de antes. |
| `changes['editGame'].isFirstChange()` | `true` la primera vez. |

Se escribe `changes['editGame']` con corchetes porque `SimpleChanges` es un objeto con claves que no se conocen de antemano (una *index signature*), igual que los errores de los formularios.

### ¿Por qué la copia con `{ ... }`?

Los objetos se pasan **por referencia**, como en Java. Si el hijo hiciera `this.game = changes['editGame'].currentValue`, `game` sería **el mismo objeto** que está en la lista del padre: al escribir en el formulario cambiaría también el listado, aunque luego no se guardara. Con `{ ...currentValue }` (el *spread* de JavaScript) se crea una copia y el original no se toca hasta que se guarda.

## La sintaxis antigua: `@Input()` y `@Output()` <NoDadoEnClase inline />

<NoDadoEnClase>
  Está en la Guía10 (input y output mediante decoradores) del [repositorio de guías](https://github.com/hokahey007/guides-angular), pero en clase se usaron las funciones `input()` y `output()`.
</NoDadoEnClase>

`input()` y `output()` llegaron en Angular 17.1 y 17.3, así que en proyectos anteriores (y en mucho código y tutoriales de hoy) verás decoradores y `EventEmitter`. Funcionan igual de cara al padre (`[nombre]` y `(seleccionado)`), pero en el hijo se leen como propiedades normales, sin paréntesis:

<Comparar titulo="El mismo hijo con las dos sintaxis">
  <Lado titulo="Decoradores (antigua)">

```ts
import { Component, EventEmitter, Input, Output } from '@angular/core';

export class AlumnoComponent {
  @Input() nombre = '';
  @Output() seleccionado = new EventEmitter<string>();

  seleccionar(): void {
    this.seleccionado.emit(this.nombre);
  }
}
```

En la plantilla del hijo: `{{ nombre }}`.

  </Lado>
  <Lado titulo="Funciones (la de clase)">

```ts
import { Component, input, output } from '@angular/core';

export class AlumnoComponent {
  nombre = input('');
  seleccionado = output<string>();

  seleccionar(): void {
    this.seleccionado.emit(this.nombre());
  }
}
```

En la plantilla del hijo: `{{ nombre() }}`.

  </Lado>
</Comparar>

<Flashcards titulo="Repaso: comunicación entre componentes">
  <Tarjeta frente="`input<T>()`">Entrada del hijo. El padre la enlaza con `[nombre]="valor"`. Se lee con `nombre()`.</Tarjeta>
  <Tarjeta frente="`input.required<T>()`">Entrada obligatoria: sin ella, error de compilación.</Tarjeta>
  <Tarjeta frente="`output<T>()`">Evento propio del hijo. Se lanza con `.emit(valor)`; el padre escucha con `(nombre)="metodo($event)"`.</Tarjeta>
  <Tarjeta frente="`$event` en un output">El valor que el hijo ha pasado a `emit`.</Tarjeta>
  <Tarjeta frente="`ngOnChanges(changes)`">Se ejecuta cuando cambia una entrada. `changes['x'].currentValue` es el valor nuevo.</Tarjeta>
  <Tarjeta frente="`@Input()` / `@Output()` + `EventEmitter`">La sintaxis antigua con decoradores. Hace lo mismo; en el hijo se lee sin paréntesis.</Tarjeta>
</Flashcards>

## Ejercicios

<Ejercicio titulo="Termina la lámpara" dificultad="media">
  Completa la Act Eval 4. El padre tiene el botón "Enchufar lámpara" / "Desenchufar", el texto del estado de conexión y "Último estado recibido: ...". El hijo pinta la bombilla con "ENCENDIDA" o "APAGADA" y tiene un interruptor que solo funciona si la lámpara está enchufada. Cada vez que se pulsa el interruptor, el hijo le manda al padre su estado.

  <Pista>El padre le pasa `enchufado` al hijo con un `input()`. El hijo avisa con un `output<boolean>()`.</Pista>
  <Pista>La bombilla solo luce si está enchufada **y** encendida: `enchufada() && encendida`.</Pista>

  <Solucion>

<NoDadoEnClase>Es una forma de terminar la actividad; en clase la lámpara se quedó sin la comunicación entre componentes.</NoDadoEnClase>

```ts title="lampara.component.ts"
import { Component, input, output } from '@angular/core';

@Component({
  selector: 'app-lampara',
  templateUrl: './lampara.component.html',
  styleUrl: './lampara.component.css'
})
export class LamparaComponent {
  enchufada = input(false);
  estadoCambiado = output<boolean>();

  protected encendida = false;

  protected pulsar(): void {
    this.encendida = !this.encendida;
    this.estadoCambiado.emit(this.encendida);
  }
}
```

```html title="lampara.component.html"
@let luce = enchufada() && encendida;

<div class="bombilla" [class.luce]="luce">
  {{ luce ? 'ENCENDIDA' : 'APAGADA' }}
</div>
<button (click)="pulsar()" [disabled]="!enchufada()">Interruptor</button>
```

```ts title="app.component.ts"
import { Component } from '@angular/core';
import { LamparaComponent } from './components/lampara/lampara.component';

@Component({
  selector: 'app-root',
  imports: [LamparaComponent],
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  enchufado = false;
  estadoLampara = false;
}
```

```html title="app.component.html"
<div class="cab">
  <span>Estado de conexión: {{ enchufado ? 'ENCHUFADA' : 'DESENCHUFADA' }}</span>
  <button (click)="enchufado = !enchufado">
    @if (enchufado) { Desenchufar } @else { Enchufar lámpara }
  </button>
  <span>Último estado recibido: {{ estadoLampara ? 'ENCENDIDA' : 'APAGADA' }}</span>
</div>

<app-lampara [enchufada]="enchufado" (estadoCambiado)="estadoLampara = $event"></app-lampara>
```

El padre no sabe nada de cómo funciona la bombilla: solo le pasa si hay corriente y escucha lo que le cuenta el hijo.

  </Solucion>
</Ejercicio>

<Ejercicio titulo="Lista y detalle" dificultad="dificil">
  `AppComponent` tiene una lista de productos. Al pulsar uno, se guarda en `seleccionado` y se le pasa a `<app-detalle>`, que muestra su título y precio y tiene un botón "Quitar selección". Al pulsarlo, el detalle avisa al padre y el padre pone `seleccionado` a `undefined`.

  <Pista>La entrada del detalle puede ser `undefined`: `producto = input<Product>()`. En la plantilla, comprueba con `@if (producto(); as p)`.</Pista>
  <Pista>El aviso no necesita llevar datos: `output<void>()` y `emit()` sin argumentos.</Pista>

  <Solucion>

```ts title="detalle.component.ts"
import { Component, input, output } from '@angular/core';
import { Product } from '../../models/product';

@Component({
  selector: 'app-detalle',
  templateUrl: './detalle.component.html'
})
export class DetalleComponent {
  producto = input<Product>();
  cerrar = output<void>();
}
```

```html title="detalle.component.html"
@if (producto(); as p) {
  <h3>{{ p.title }}</h3>
  <p>{{ p.price }} €</p>
  <button (click)="cerrar.emit()">Quitar selección</button>
} @else {
  <p>Elige un producto</p>
}
```

```html title="app.component.html"
@for (product of products; track product.id) {
  <button (click)="seleccionado = product">{{ product.title }}</button>
}

<app-detalle [producto]="seleccionado" (cerrar)="seleccionado = undefined"></app-detalle>
```

```ts title="app.component.ts (lo que importa)"
// En @Component: imports: [DetalleComponent]
products: Product[] = [];
seleccionado: Product | undefined;
```

`@if (producto(); as p)` guarda el valor en `p` para no llamar al signal cada vez. No salió en clase, pero es parte de la sintaxis de `@if` <NoDadoEnClase inline />.

  </Solucion>
