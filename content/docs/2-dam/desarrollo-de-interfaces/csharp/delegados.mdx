Un **delegado** es un tipo que guarda **métodos**. Es la pieza sobre la que se montan las lambdas y los eventos, y por tanto los botones y demás controles de una interfaz gráfica. Toda la clase del 09/11 se hizo en `Program.cs` con una calculadora.

<DeClase fecha="09/11" proyecto="Clase1" nota="PDF Creación de interfaces, tema 1, apartados 1.4 y 1.5 (pág. 5)" />

<Callout type="idea" title="Lo que vas a aprender">
  - Declarar un delegado y asignarle un método, de la forma larga y de la corta.
  - Invocarlo y reasignarlo.
  - Meter varios métodos en el mismo delegado (*multicast*) con `+=` y quitarlos con `-=`.
  - Por qué con un multicast solo recibes lo que devuelve el último método, y cómo recoger todos con `GetInvocationList()`.
  - Guardar en un delegado métodos `static` y métodos de un objeto.
</Callout>

## Qué es un delegado

Un delegado describe una **firma**: qué devuelve un método y qué parámetros recibe. Cualquier método con esa misma firma se puede guardar en una variable de ese tipo y llamarse a través de ella.

```csharp title="Program.cs"
delegate int Operacion(int a, int b);
```

Esto se lee: "`Operacion` es el tipo de los métodos que reciben dos `int` y devuelven un `int`". Los PDF de la asignatura lo definen como *"un contrato entre el emisor y el receptor"*: quien usa el delegado no sabe qué método hay dentro, solo que cumple esa firma.

Si vienes de Java, es lo mismo que una **interfaz funcional** (como `IntBinaryOperator`), pero con su propia palabra clave y sin tener que inventar un nombre de método: el delegado se llama directamente, `op(4, 5)`.

<Callout type="warn" title="Un delegado es un tipo">
  Como una clase, el `delegate` va **después** de las instrucciones de nivel superior en `Program.cs`. Si lo subes arriba sale el error CS8803 (se probó en clase). Lo tienes explicado en [Visual Studio y el proyecto Clase1](/docs/2-dam/desarrollo-de-interfaces/csharp/visual-studio-y-proyecto#el-orden-importa).
</Callout>

## La clase, paso a paso

<Steps>
  <Step>

#### El punto de partida

  `Program.cs` dividido con comentarios de sección: arriba la ejecución y abajo las definiciones. Está el delegado `Operacion` y la clase `Calculadora` con dos métodos **estáticos**, `Sumar` y `Restar`, que escriben la operación y devuelven el resultado.

  </Step>
  <Step>

#### Asignar un método

  Primero con `new`, y después con la **forma corta**, que es la que se queda:

```csharp
// Primero, con new:
Operacion op = new Operacion(Calculadora.Sumar);

// Después, la forma corta (sustituye a la línea anterior):
Operacion op = Calculadora.Sumar;
```

  Fíjate en que `Calculadora.Sumar` va **sin paréntesis**: no se llama al método, se guarda.

  </Step>
  <Step>

#### Invocarlo como si fuera un método

  `op(4, 5);` llama a lo que haya dentro. IntelliSense enseña la firma `int Operacion(int a, int b)`. Sale `Suma: 4 + 5 = 9`.

  </Step>
  <Step>

#### Reasignarlo

  Si cambias la asignación a `Calculadora.Restar`, la misma llamada `op(4, 5)` escribe `Resta: 4 - 5 = -1`. El delegado puede apuntar a **cualquier** método con la misma firma.

  </Step>
  <Step>

#### Multicast con `+=`

  Con `op += Calculadora.Restar;` se **añade** un método más. Ahora una sola llamada `op(4, 5)` ejecuta los dos, en el orden en que se añadieron: `Suma: 4 + 5 = 9` y después `Resta: 4 - 5 = -1`.

  </Step>
  <Step>

#### Recoger cada resultado con `GetInvocationList()`

  `op(4, 5)` se sustituye por un `foreach` que recorre la lista de métodos del delegado y llama a cada uno por separado.

  </Step>
  <Step>

#### Un método de instancia

  A `Restar` se le quita `static`. `op += Calculadora.Restar;` deja de compilar y hay que crear un objeto: `op += calc.Restar;`.

  </Step>
  <Step>

#### Campos privados con estado

  `Calculadora` recibe dos campos, `val1 = 6` y `val2 = 3`, y `Restar` pasa a usarlos. La resta sale `6 - 3 = 3`.

  </Step>
</Steps>

## Asignar, invocar y reasignar

Así lo cuenta el PDF (apartado 1.4):

```csharp title="Ejemplo del PDF, 1.4"
using System;

delegate int Operacion(int x, int y);

class Program
{
    static int Sumar(int a, int b) => a + b;
    static int Restar(int a, int b) => a - b;

    static void Main()
    {
        Operacion op = Sumar;                    // Asignar el método Sumar
        Console.WriteLine("Suma: " + op(5, 3));  // Suma: 8
        op = Restar;                             // Reasignar a Restar
        Console.WriteLine("Resta: " + op(5, 3)); // Resta: 2
    }
}
```

- **Asignar**: `Operacion op = Sumar;`. El método tiene que tener **la misma firma** que el delegado (dos `int`, devuelve `int`). Los nombres de los parámetros no importan: el delegado usa `x` e `y` y los métodos, `a` y `b`.
- **Invocar**: `op(5, 3)`, como si `op` fuera un método.
- **Reasignar** con `=`: el delegado deja de apuntar a `Sumar` y apunta a `Restar`.
- `=> a + b` es un método escrito en una línea. Lo verás en [Validador, métodos anónimos y lambdas](/docs/2-dam/desarrollo-de-interfaces/csharp/validador-y-lambdas).

## Multicast: varios métodos en un delegado

Un delegado puede guardar **varios métodos** a la vez:

- `+=` **añade** un método al final.
- `-=` **quita** un método (aparece en los apuntes; en clase se usa el 19/11 con los eventos).
- Al invocar el delegado se ejecutan **todos**, en el orden en que se añadieron.

El PDF (apartado 1.5) lo explica así: *"Los delegados pueden contener múltiples métodos. Cuando se llama al delegado, se ejecutan todos los métodos asignados en el orden en que fueron añadidos"*. Su ejemplo, que en el PDF es otro programa con su propio `Main` y los mismos `Sumar` y `Restar` de una línea:

```csharp title="Ejemplo del PDF, 1.5 (dentro de Main)"
Operacion op = Sumar;
op += Restar;                            // Añadir Restar
foreach (Operacion metodo in op.GetInvocationList())
{
    Console.WriteLine(metodo(5, 3));     // 8 y 2
}
```

Escribe `8` y `2`: cada vuelta llama a un método de la lista. Lo de `GetInvocationList()` lo explicamos justo debajo.

### El problema del valor de retorno

Si llamas directamente a un delegado multicast que devuelve algo, **se ejecutan todos los métodos, pero solo recibes lo que devuelve el último**:

```csharp title="Ejemplo propio"
Operacion op = Calculadora.Sumar;
op += Calculadora.Restar;
int r = op(4, 5);   // escribe la suma y la resta, pero r vale -1
```

En clase se llamó a `op(4, 5)` sin guardar el resultado; la variable `r` la hemos añadido para que se vea qué se recibe.

Por eso, para tener **cada** resultado, se recorre la lista de métodos con `GetInvocationList()`. Es un método que tienen todos los delegados (viene de `System.Delegate`):

```csharp title="Program.cs (09/11, mitad de la clase)"
// See https://aka.ms/new-console-template for more information
//Ejecución de la función principal
Operacion op = Calculadora.Sumar;
op += Calculadora.Restar;

// Ejecucion del delegado
foreach (Operacion operacion in op.GetInvocationList())
{
    int resultado = operacion(10, 5);
    Console.WriteLine($"Resultado: {resultado}");
}

// Definiciones
// Funciones
delegate int Operacion(int a, int b);

// Clases
class Calculadora
{
    public static int Sumar(int a, int b)
    {
        int suma = a + b;
        Console.WriteLine($"Suma: {a} + {b} = {suma}");
        return suma;
    }

    public static int Restar(int a, int b)
    {
        int resta = a - b;
        Console.WriteLine($"Resta: {a} - {b} = {resta}");
        return resta;
    }
}
```

<Terminal titulo="Consola de depuración de Microsoft Visual Studio">
{`Suma: 10 + 5 = 15
Resultado: 15
Resta: 10 - 5 = 5
Resultado: 5`}
</Terminal>

Cada vuelta del `foreach` saca **un** método de la lista (`operacion`, del tipo `Operacion`) y lo llama con `(10, 5)`. Así cada resultado se queda en su variable. Visual Studio marca de paso que `operacion` "no es NULL aquí".

## Métodos estáticos y de instancia

Un método `static` es de la **clase**: se pasa al delegado con el nombre de la clase, `Calculadora.Sumar`. Un método **de instancia** es de un **objeto**: hay que crearlo antes y pasar `objeto.Metodo`.

En clase se le quitó `static` a `Restar`. Entonces `op += Calculadora.Restar;` <Dudoso nota="Visual Studio marca un error, pero el texto no se lee. Todo indica que es porque Restar acaba de dejar de ser static.">deja de compilar</Dudoso>, y hay que crear una `Calculadora`:

```csharp title="Program.cs"
Operacion op = Calculadora.Sumar;          // estático: con el nombre de la clase
Calculadora calc = new Calculadora();
op += calc.Restar;                         // de instancia: con el objeto
```

Un mismo delegado puede **mezclar** métodos estáticos y de instancia.

<NoDadoEnClase titulo="El error de llamar a un método de instancia desde la clase">
  En clase no se lee el código del error. Lo normal en este caso es **CS0120**: hace falta una referencia de objeto para usar un miembro que no es estático. Es el mismo error que en Java te da llamar a un método no estático desde `main`.
</NoDadoEnClase>
