`HttpClient` es el servicio de Angular para hacer **peticiones HTTP** (GET, POST, PUT, DELETE…) a una API. Se usa **siempre desde un servicio**, nunca desde el componente, y no devuelve los datos directamente: devuelve un **`Observable`**, una respuesta que llegará más tarde.

<DeClase fecha="27/10, 28/10" proyecto="angular-http y proj-fakestore" />

<Callout type="idea" title="Lo que vas a aprender">
  - Activar `HttpClient` con `provideHttpClient()`.
  - Escribir los modelos de la API con `interface` y `Omit`.
  - Montar un servicio CRUD completo con `get`, `post`, `put` y `delete` tipados.
  - Entender qué es un `Observable` y por qué hace falta `subscribe`.
  - Cargar los datos en `ngOnInit` y pintarlos con `@for`.
</Callout>

Las dos primeras son públicas y devuelven datos de prueba: aceptan `POST`, `PUT` y `DELETE`, pero **no guardan los cambios** de verdad. Antes de programar, abre la URL en el navegador o en Postman para ver qué JSON devuelve. En clase se hizo así con `/posts`, `/posts/1/comments` y los productos.

## 1. Activar HttpClient

`HttpClient` no está disponible hasta que se registra su *provider* en `app.config.ts`:

```ts title="src/app/app.config.ts"
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';

import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes),
    provideHttpClient()
  ]
};
```

<NoSeVio titulo="provideHttpClient() en clase">
  En las capturas no se ve dónde se registra `provideHttpClient()` (28/10): como las peticiones funcionan, tiene que estar en `app.config.ts`. El archivo de arriba es como queda en Angular 19, siguiendo la unidad 8 de HTTP de las guías.
</NoSeVio>

Una de las preguntas finales de la Act 8 es **qué pasaría si se quitara `provideHttpClient()`**. La respuesta <NoDadoEnClase inline />: la aplicación compila, pero al abrirla la consola da un `NullInjectorError` que dice que no hay *provider* para `HttpClient` (en Angular 19 sale como `_HttpClient`). El servicio pide un `HttpClient` y el inyector no sabe crearlo. En `proj-fakestore`, como es `AppComponent` quien pide el servicio, Angular ni siquiera puede crear el componente raíz y la página se queda en blanco.

## 2. El modelo de datos

<DeClase fecha="27/10" proyecto="angular-http" />

Primero se escribe una **interfaz** de TypeScript con la forma del JSON. El truco de clase: pegar un JSON de ejemplo como comentario, escribir los campos debajo y borrar el comentario.

```ts title="src/app/models/post.model.ts"
export interface Post {
    userId: number;
    id: number;
    title: string;
    body: string;
}

export type NewPost = Omit<Post, 'id'>;
```

- Una `interface` de TypeScript solo existe para el compilador: no genera código, solo comprueba tipos. Es como un DTO de Java sin métodos.
- **`Omit<Post, 'id'>`** crea un tipo nuevo con todos los campos de `Post` **menos** `id`. Es lo que se manda al crear: el `id` lo pone el servidor.
- Se probó `id?: number` (opcional, de tipo `number | undefined`), pero al final se dejó `id: number` y el tipo aparte. En `proj-game` sí se usa `id?` (05/11).

```ts title="src/app/models/comment.model.ts"
export interface Comment {
    postId: number;
    id: number;
    name: string;
    email: string;
    body: string;
}

export type NewComment = Omit<Comment, 'id'>;
```

<Callout type="warn" title="Ojo con el nombre Comment">
  `Comment` también es un tipo del navegador (el nodo de comentario del DOM). Si se te olvida `import { Comment } from '../models/comment.model'`, TypeScript usa el del DOM y salen errores de tipos raros. El 27/10 salieron errores de tipos en la línea del signal de comentarios hasta que se importó el modelo, y lo más probable es que fuera por esto <Dudoso nota="No se lee el mensaje de error en las capturas: que fuera el `Comment` del DOM es una deducción." />.
</Callout>

## 3. Una interfaz genérica para todos los servicios

<DeClase fecha="27/10" proyecto="angular-http" />

En clase se generó con `ng g interface interface/CRUD` un **contrato** que implementan todos los servicios de datos:

```ts title="src/app/interface/crud.ts"
import { Observable } from "rxjs";

export interface CRUD<T, S> {
    getAll(): Observable<T[]>;
    getById(id:number):Observable<T>;
    create(entity:S):Observable<T>;
    update(id:number, entity:S):Observable<T>;
    delete(id:number):Observable<void>;
}
```

- **`T`** es la entidad que **devuelve** la API (`Post`, con `id`).
- **`S`** es la que se **envía** (`NewPost`, sin `id`).
- Todos los métodos devuelven `Observable`, porque las respuestas llegan más tarde. `delete` devuelve `Observable<void>`: no interesa el cuerpo de la respuesta.
- Es igual que una interfaz genérica de Java (`interface Crud<T, S>`). Si escribes `implements CRUD<Post>` con un solo tipo, sale `Generic type 'CRUD<T, S>' requires 2 type arguments`.

  lenguaje="ts"
  codigo={`import { HttpClient } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { Post, NewPost } from '../models/post.model';
import { CRUD } from '../interface/crud';
import { Observable } from 'rxjs';

@Injectable({
  providedIn: 'root'
})
export class PostsService implements CRUD<Post, NewPost> {

  private readonly http = inject(HttpClient);
  private readonly apiUrl = 'https://jsonplaceholder.typicode.com/posts';

  getAll(): Observable<Post[]> {
    return this.http.get<Post[]>(this.apiUrl);
  }
  getById(id: number): Observable<Post> {
    return this.http.get<Post>(\`\${this.apiUrl}/\${id}\`);
  }
  create(entity: NewPost): Observable<Post> {
    return this.http.post<Post>(this.apiUrl, entity);
  }
  update(id: number, entity: NewPost): Observable<Post> {
    return this.http.put<Post>(\`\${this.apiUrl}/\${id}\`, entity);
  }
  delete(id: number): Observable<void> {
    return this.http.delete<void>(\`\${this.apiUrl}/\${id}\`);
  }
}`}
>

  </Paso>
  <Paso lineas="12" titulo="Se inyecta HttpClient">

  </Paso>
  <Paso lineas="13" titulo="La URL base, en una propiedad">
    Así no se repite en cada método. Si cambias de API, cambias una línea.
  </Paso>
  <Paso lineas="15-17" titulo="GET de la lista">
    `get<Post[]>(url)` hace un `GET` y le dice a TypeScript que el JSON será un array de `Post`. Devuelve `Observable<Post[]>`.
  </Paso>
  <Paso lineas="18-20" titulo="GET por id">

  </Paso>
  <Paso lineas="21-23" titulo="POST: crear">

  </Paso>
  <Paso lineas="24-26" titulo="PUT: actualizar">
    `put<Post>(url, cuerpo)` sustituye el recurso con ese id.

| Método | Petición | Devuelve |
| --- | --- | --- |
| `http.get<T>(url)` | `GET` | `Observable<T>` |
| `http.post<T>(url, body)` | `POST` con `body` en JSON | `Observable<T>` |
| `http.put<T>(url, body)` | `PUT` con `body` en JSON | `Observable<T>` |
| `http.delete<T>(url)` | `DELETE` | `Observable<T>` |

### Los errores de tipos que salieron

`HttpClient` tiene **15 sobrecargas** de cada método (según `responseType`, `observe`…), así que cuando algo falta TypeScript elige una que no esperas:

- **Sin el genérico**, `this.http.get(this.apiUrl)` devuelve `Observable<Object>`, y no se puede devolver como `Observable<Post[]>`.
- **Con el genérico equivocado**, `get<Post>()` en `getAll`: `Observable<Post> is not assignable to Observable<Post[]>`.
- **Sin la URL**, `get<Post>()` hace que el editor elija la sobrecarga de `responseType: 'arraybuffer'` y sale un `Observable<ArrayBuffer>`. Al poner la URL coge la buena (la de `responseType: 'json'`).
- **Sin `return`** (el error más repetido en clase): *"A function whose declared type is neither 'undefined', 'void', nor 'any' must return a value"*.

</NoSeVio>

## 5. Observable y subscribe

Un `Observable` es como un pedido: *"cuando lleguen los posts, avísame y dámelos"*. La petición tarda, y JavaScript no se queda esperando: sigue ejecutando el resto del código. Para recibir los datos hay que **suscribirse**:

```ts title="posts.component.ts"
ngOnInit(): void {
  this.postsService.getAll().subscribe((posts) => {
    console.log(posts);   // primero, para comprobar que llegan
    this.posts = posts;   // luego, se guardan en el componente
  });
}
```

- La función que le pasas a `subscribe` (una *arrow function*, como una lambda de Java) se ejecuta **cuando llega la respuesta**, no antes.
- Lo que haya después del `subscribe` se ejecuta **antes** de que lleguen los datos.
- El *tooltip* de `subscribe` enseña que acepta una función o un objeto `Observer`, y que devuelve una `Subscription`.
- Un `Observable` de `HttpClient` **no hace la petición hasta que alguien se suscribe** <NoDadoEnClase inline />. Si llamas a `getAll()` y no te suscribes, no sale nada en la pestaña Network.

## Gestionar el error de la petición <NoDadoEnClase inline />

En clase, el `subscribe` solo recibía los datos. Si la API falla (sin red, un 404, un 500), no pasa nada visible: la lista se queda vacía y el error solo sale en la consola.

<Comparar titulo="Suscribirse teniendo en cuenta el error">
  <Lado tipo="evitar">

```ts
this.productService.getProducts().subscribe(products => {
  this.products = products;
});
```

Solo el caso bueno. Si falla, el usuario no se entera.

  </Lado>
  <Lado tipo="bien">

```ts
this.loading = true;
this.productService.getProducts().subscribe({
  next: (products) => {
    this.products = products;
    this.loading = false;
  },
  error: () => {
    this.error = 'No se han podido cargar los productos';
    this.loading = false;
  }
});
```

Con un objeto `{ next, error }` tratas los dos casos y puedes pintar los estados de carga y error con `@if`.

  </Lado>
</Comparar>

<NoDadoEnClase>
  La versión con `{ next, error }` no se dio en clase. Es la forma estándar y la que usa el material de lo que falta por dar (listado con estados de carga, vacío y error). El manejo de errores con `catchError` está en la unidad 11 de las guías.
</NoDadoEnClase>

  <Pista>Copia la estructura de `PostsService`: cambian el modelo y la URL.</Pista>
  <Pista>Para tachar, un class binding: `[class.hecho]="todo.completed"` y `.hecho { text-decoration: line-through; }`.</Pista>

  <Solucion>

```ts title="models/todo.model.ts"
export interface Todo {
  userId: number;
  id: number;
  title: string;
  completed: boolean;
}

export type NewTodo = Omit<Todo, 'id'>;
```

```ts title="services/todos.service.ts"
import { HttpClient } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { Observable } from 'rxjs';
import { CRUD } from '../interface/crud';
import { NewTodo, Todo } from '../models/todo.model';

@Injectable({ providedIn: 'root' })
export class TodosService implements CRUD<Todo, NewTodo> {
  private readonly http = inject(HttpClient);
  private readonly apiUrl = 'https://jsonplaceholder.typicode.com/todos';

  getAll(): Observable<Todo[]> {
    return this.http.get<Todo[]>(this.apiUrl);
  }
  getById(id: number): Observable<Todo> {
    return this.http.get<Todo>(`${this.apiUrl}/${id}`);
  }
  create(entity: NewTodo): Observable<Todo> {
    return this.http.post<Todo>(this.apiUrl, entity);
  }
  update(id: number, entity: NewTodo): Observable<Todo> {
    return this.http.put<Todo>(`${this.apiUrl}/${id}`, entity);
  }
  delete(id: number): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}
```

```ts title="pages/todos/todos.component.ts"
import { Component, inject, OnInit } from '@angular/core';
import { TodosService } from '../../services/todos.service';
import { Todo } from '../../models/todo.model';

@Component({
  selector: 'app-todos',
  templateUrl: './todos.component.html',
  styleUrl: './todos.component.css'
})
export class TodosComponent implements OnInit {
  private readonly todosService = inject(TodosService);
  protected todos: Todo[] = [];

  ngOnInit(): void {
    this.todosService.getAll().subscribe(todos => this.todos = todos);
  }
}
```

```html title="pages/todos/todos.component.html"
<ul>
  @for (todo of todos; track todo.id) {
    <li [class.hecho]="todo.completed">{{ todo.title }}</li>
  }
</ul>
```

```css title="pages/todos/todos.component.css"
.hecho { text-decoration: line-through; }
```

Y que `provideHttpClient()` esté en `app.config.ts`.

  </Solucion>
