## 2. Conceptos y patrones

- **La capa de datos va en tres piezas:** `PokeApi` (Retrofit) → `PokemonDataSource` (interfaz) → `PokemonRemoteDataSource` (implementación) → `PokemonRepository` / `PokemonRepositoryImpl`. Cada capa recibe la de debajo por `@Inject constructor`.
- **DTO y modelo son cosas distintas:** las data class del JSON (`PokemonResult`, `PokemonSprites`, `PokemonListResult`, `PokemonListItemResult`) se convierten al modelo `Pokemon(id, name, pokemonImageUrl)` con una **función de extensión `toModel()`**. Dentro de ella, `this` es el objeto que la llama.
- **`Response<T>` de Retrofit:** sirve para leer el código HTTP. Se mira `isSuccessful` y después `body()`, que puede ser null; de ahí el `!!`.
- **Tipo nullable** `Pokemon?` cuando puede no haber resultado.
- **Listado + detalle:** la lista de la PokeAPI solo trae `name` y `url`, así que se hace una petición de detalle por cada pokémon (N+1 peticiones) para tener la imagen.
- **Colecciones:** `mutableListOf<T>()`, `add()` y `for (item in lista)`.
- **Hilt:**
  - `@HiltAndroidApp` va en la `Application`. No `@AndroidEntryPoint`: ese fue el error que se corrigió en clase.
  - `@AndroidEntryPoint` va en la Activity.
  - Módulo con `@Binds` (puede ser una `interface` o una abstract class) para atar una interfaz a su implementación.
  - Módulo con `@Provides` (una `class`) para objetos que hay que construir a mano, como Retrofit.
  - `@Singleton` para que haya una sola instancia.
- La `Application` propia hay que **registrarla en el manifest** con `android:name`, y la app necesita el permiso **INTERNET**.
- `TODO("Not yet implemented")` sirve para dejar funciones a medias: lanza `NotImplementedError` si se llama.
- Trucos del IDE que salieron:
  - el asistente New Kotlin Class/File (class, interface, data class, object…);
  - Alt+Intro para importar;
  - el aviso «Unused variable»;
  - Surround with try/catch;
  - los tooltips de documentación.

class PokemonRemoteDataSource @Inject constructor(
    private val _api: PokeApi
) : PokemonDataSource {
    override suspend fun readAllPokemon(): List<Pokemon> {
        val response = _api.readAllPokemon()
        val pokemons = mutableListOf<Pokemon>()
        if (response.isSuccessful) {
            val body = response.body()!!
            for (item in body.results) {
                val pokemon = readPokemonByName(item.name)
                pokemons.add(pokemon!!)
            }
        } else {
            // Mostrar un error!

## 5. Lo dudoso o ilegible

- **`@InstallIn(Singleton::class)` en AppModule**, con el import `jakarta.inject.Singleton`, se lee igual en 3 capturas. En Hilt hay que poner `SingletonComponent::class`, como en NetworkModule. Probablemente es un error que se corregiría más tarde.
- **La `baseUrl` `"https://pokeapi.co/api/v2"` no termina en `/`**, y las rutas empiezan por `/pokemon`. Con eso, Retrofit 3 lanza una excepción (la baseUrl tiene que acabar en `/`). Además, una ruta que empieza por `/` quita el `/api/v2`. Lo correcto sería `baseUrl("https://pokeapi.co/api/v2/")` con `@GET("pokemon")`. En clase aún no se había ejecutado.
- **`frontDefault` y `front_default`:** el JSON trae `front_default`, y sin `@SerializedName("front_default")` Gson lo dejaría en null. Esa anotación no aparece en ninguna captura.
- En `PokemonRemoteDataSource` quedó una sobrecarga sobrante, `readPokemonById()` sin parámetros. Se selecciona para borrarla (25:12) y aún aparece en la captura de 25:21.
- `PokemonRepositoryImpl` termina con `TODO()` y con la firma vieja `readPokemonById()`.
- La función de `NetworkModule` se llama `provideHttpClient`, pero devuelve `PokeApi`, no un `OkHttpClient`.
- El permiso CAMERA aparece y desaparece (34:19 lo añade, 36:57 lo quita y 37:03 vuelve a salir). Lo más probable es que fuera solo un ejemplo y se quitara al final: en 37:25 solo queda INTERNET.
