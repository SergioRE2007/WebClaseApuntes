## 2. Conceptos y patrones

**Room 3 (paquete `androidx.room3`)**
- `@Entity` sobre una `data class`, con `@PrimaryKey` en el `id`. Un campo opcional se declara nullable (`String?`).
- `@Dao` sobre una `interface`. Todas las funciones son `suspend`. `@Insert` aparece sobrecargado, con `vararg` y con `List`; también hay `@Update` y `@Query` con SQL.
- `@Database(entities = [...], version = 1)` sobre una **clase abstracta que hereda de `RoomDatabase()`**, con una función abstracta por DAO. Room genera la implementación.
- **Room comprueba el SQL al compilar (con KSP).** Si una consulta está mal, el build falla con `SQLITE_ERROR` o con "Not sure how to convert the query result".
- **El nombre de la tabla no puede ser un parámetro.** Los `:nombre` solo valen para valores (`WHERE id = :id`). Por eso fallaba `FROM :pokemon`; lo correcto es `FROM pokemon`, o el nombre que se ponga en `tableName`.
- Si un parámetro de la función no se usa en la consulta, sale el error `Unused parameter: id`.
- Aviso *Schema export directory was not provided*: se quita con `exportSchema = false` en `@Database` o configurando el directorio del esquema. En clase solo se vio el aviso, no cómo arreglarlo.

**Hilt**
- Módulo `@Module @InstallIn(SingletonComponent::class)` como **`class`** con `@Provides`. Es el patrón `@Provides`, distinto del `abstract class` + `@Binds` de la ToDoApp: `@Provides` se usa cuando hay que **construir** el objeto (Room), y `@Binds` cuando solo se ata una interfaz a su implementación.
- `@ApplicationContext context: Context` para recibir el contexto de la app en un `@Provides`.
- **Provides encadenados:** `providesPokemonDao(db: PokemonDatabase)` recibe la BD que Hilt ya sabe crear con el otro `@Provides`.
- `@HiltAndroidApp` en la `Application`, `android:name` en el manifest y `@AndroidEntryPoint` en la Activity.
- `@HiltViewModel` necesita `@Inject constructor()`, **aunque no tenga parámetros**. Sin eso, Hilt da error.
- Un error de Room en KSP hace que también falle el procesado de Hilt ("Processing did not complete"). Hay que leer el **primer** error de la lista.

**ViewModel y estado**
- En una **Activity** (no en un composable) el ViewModel se obtiene con el delegado `by viewModels()`, y hay que indicar el tipo (`val viewModel: MainViewModel by viewModels()`). Sin `by`, no compila.
- Propiedad respaldada: `private val _uiState = MutableStateFlow(false)` y `val uiState: StateFlow<Boolean> get() = _uiState.asStateFlow()`.
- `init { viewModelScope.launch { ... } }` y `delay` con `Duration` (`10.seconds`, `10_000L.milliseconds`, de `kotlin.time.Duration.Companion`).

**SplashScreen API**
- `installSplashScreen()` **antes** de `super.onCreate()`.
- `setKeepOnScreenCondition { Boolean }`: la condición se comprueba en cada frame, y el splash sigue mientras devuelva `true`. Por eso se niega el estado: `!viewModel.uiState.value`.
- La documentación también enseña `setOnExitAnimationListener { splashScreenViewProvider -> ... }` para animar la salida. En clase no se usó.
- Tema: hereda de `Theme.SplashScreen`, con `postSplashScreenTheme` y `windowSplashScreenBackground`. En clase solo se leyó en la documentación; no se ve que se tocara `themes.xml`.

**Material 3 (teoría):** *Loading indicator* y *Contained loading indicator* de Material 3 Expressive. Solo se vio la página de diseño.

**`data/PokemonDatabase.kt`**
```kotlin
import androidx.room3.Database
import androidx.room3.RoomDatabase

@Database(
    entities = [PokemonEntity::class],
    version = 1,
)
abstract class PokemonDatabase(): RoomDatabase() {
    abstract fun pokemonDao(): PokeDao
}
```

**`di/AppModule.kt`**
```kotlin
@Module
@InstallIn(SingletonComponent::class)
class AppModule {
    @Provides
    fun providesDatabase(@ApplicationContext context: Context): PokemonDatabase {
        val db = Room.databaseBuilder<PokemonDatabase>(
            context = context,
            name = "pokemon_db"
        ).build()
        return db
    }

    @Provides
    fun providesPokemonDao(db: PokemonDatabase): PokeDao {
        return db.pokemonDao()
    }
}
```

**`MainViewModel.kt`**
```kotlin
@HiltViewModel
class MainViewModel @Inject constructor(): ViewModel() {
    private val _uiState: MutableStateFlow<Boolean> = MutableStateFlow(value = false)
    val uiState: StateFlow<Boolean>
        get() = _uiState.asStateFlow()

    init {
        viewModelScope.launch {
            delay(duration = 1.seconds)   // primero 10.seconds
            _uiState.value = true
        }
    }
}
```

**`MainActivity.kt`**
```kotlin
@AndroidEntryPoint
class MainActivity : ComponentActivity() {
    val viewModel: MainViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        val splashScreen = installSplashScreen()
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()

        splashScreen.setKeepOnScreenCondition { !viewModel.uiState.value }
        setContent {
            RoomTheme {
                Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
                    Greeting(name = "Android", modifier = Modifier.padding(innerPadding))
                }
            }
        }
    }
}
```

## 4. Librerías, anotaciones y versiones
- **Room 3:** `androidx.room3:room3-runtime:3.0.3` y `room3-compiler:3.0.3` (con `ksp`), escritas directamente en el build, sin pasar por el catálogo. Anotaciones: `@Entity`, `@PrimaryKey`, `@Dao`, `@Insert`, `@Update`, `@Query` y `@Database`. Clases: `Room`, `RoomDatabase`.
- **Hilt 2.60.1:** `hilt-android` y `hilt-android-compiler` (con `ksp`). Anotaciones: `@Module`, `@Provides`, `@InstallIn(SingletonComponent::class)`, `@ApplicationContext`, `@HiltAndroidApp`, `@AndroidEntryPoint`, `@HiltViewModel` y `@Inject` (de `javax.inject.Inject`).
- **KSP 2.3.12.** Las tareas de Gradle que salen son `kspDebugKotlin` y `hiltJavaCompileDebug`.
- **SplashScreen:** `androidx.core:core-splashscreen:1.2.0`, con `installSplashScreen`, `setKeepOnScreenCondition`, `setOnExitAnimationListener`, `SplashScreenViewProvider` y el tema `Theme.SplashScreen`.
- **Lifecycle:** `androidx.lifecycle:lifecycle-viewmodel-ktx:2.11.0`, con `ViewModel` y `viewModelScope`. `activity-ktx:1.13.0` se añadió y luego se quitó. `viewModels()` viene de `androidx.activity`, que ya llega con `activity-compose`.
- **Corrutinas y Flow:** `MutableStateFlow`, `StateFlow`, `asStateFlow`, `launch`, `delay`, y `kotlin.time.Duration.Companion.seconds` / `milliseconds`.
- **Resto:** AGP 9.2.1, Kotlin 2.2.10 y Compose BOM 2026.02.01. Emuladores Pixel 7a con API 37.1 y Pixel 10 (Android 17). En el build sale un aviso que recomienda un AGP más nuevo para compileSdk 37.1.
