## 2. Conceptos y patrones

- **Estado observable con StateFlow:** el ViewModel expone un `MutableStateFlow` con la lista y la pantalla lo convierte en `State` con `collectAsStateWithLifecycle()` y el delegado `by`. Así se contesta el TODO de "¿cómo hago esto observable?".
- **Diferencia entre `collectAsState` y `collectAsStateWithLifecycle`:** la segunda deja de recoger el flujo cuando la pantalla baja de `STARTED` (por defecto).
- **ViewModel con Hilt, paso a paso:** `ViewModel()` → `@Inject constructor(...)` → `@HiltViewModel` → dependencia por interfaz (`TaskRepository`) con el prefijo `_`.
- **Estado de formularios con `TextFieldState`** dentro del ViewModel. La pantalla solo lo enlaza con `OutlinedTextField(state = ...)` y el texto se lee con `.text.toString()`.
- **La pantalla no tiene lógica:** el botón llama a una **referencia a función** (`viewModel::onCreate`).
- **El ViewModel se obtiene en la pantalla** con `viewModel: X = hiltViewModel()` como parámetro por defecto, y `modifier: Modifier = Modifier`.
- **Argumentos con nombre** en las llamadas Kotlin. `TODO()` sirve de marcador y lanza `NotImplementedError` si se ejecuta.
- **Una propiedad `val` tiene que inicializarse** o ser `abstract`.
- **Repositorio en memoria** con `@Inject constructor()`, una `mutableListOf` privada (`_taskList`), `readAll() = _taskList.toList()` e id autoincremental (`nextId`).
- **Navegación con rutas tipadas** (repaso): `object` para los destinos sin datos y `class TaskDetail(val id: Int)` para los que llevan datos. Las pantallas reciben callbacks (`toCreate`, `toDetail`).
- **Depuración de Compose en Android Studio:** breakpoints, variables, frames, Step Into, Resume y Recomposition State.
- **Deuda técnica** marcada con TODO (las fechas como `String`).

```kotlin
@Composable
fun TaskListScreen(
    modifier: Modifier = Modifier.Companion,
    toCreate: () -> Unit,
    toDetail: (Int) -> Unit,
    viewModel: TaskListViewModel = hiltViewModel(),
) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    Scaffold(
        modifier = Modifier.fillMaxSize(),
        floatingActionButton = {
            FloatingActionButton(onClick = toCreate) {
                Icon(painterResource(id = R.drawable.add_24px), contentDescription = "Create")
            }
        }
    ) { innerPadding ->
        val modifier = Modifier.consumeWindowInsets(innerPadding).padding(innerPadding)
        LazyColumn(modifier = modifier) {
            items(items = viewModel.readAll(), key = { it.id }) {
                TaskCard(
                    toDetail = { toDetail(it.id) },
                    title = it.title,
                    description = it.description,
                    isCompleted = it.isCompleted
                )
            }
        }
    }
}
```

```kotlin
@Serializable
sealed class Route(val route: String) {
    @Serializable object TaskList : Route(route = "taskList")
    @Serializable object TaskCreate : Route(route = "taskCreate")
    @Serializable class TaskDetail(val id: Int) : Route(route = "taskDetail/$id")
}

composable<Route.TaskDetail> { backStackEntry ->
    val detail: Route.TaskDetail = backStackEntry.toRoute()
    TaskDetailScreen(id = detail.id)
}

@Module
@InstallIn(SingletonComponent::class)
abstract class ApplicationModule {
    @Binds @Singleton
    abstract fun bindTaskRepository(repository: TaskRepositoryInMemory): TaskRepository
}

interface TaskRepository {
    fun readAll(): List<Task>
    fun readOne(id: Int): Task
    fun create(title: String, description: String, limitDate: String): Task
    fun complete(id: Int)
    fun uncomplete(id: Int)
```

## 5. Lo dudoso o ilegible

- **img029:** no existe en la carpeta.
- **Fecha fija:** se lee `"9999.31.12"` en varias capturas (img069, img074, img081 y la variable del depurador). Es un formato raro (año.día.mes), pero es lo que se repite.
- **`if (_taskList.add(newTask)) nextId++`:** en img084 se lee `!taskList.add` y en img085 `_taskList.add` sin `!`. Me quedo con la segunda, que es la que tiene sentido.
- **Despiste corregido en directo:** en img068 se escribe `description = titleState.text.toString()`, y en img069 ya está corregido a `descriptionState`.
- **Al depurar, `title = ""`:** solo se había escrito texto en un campo (`description = "zghehrhe"`). Los campos no tienen `label`, así que en la app no se distinguen.
- **Falta usar el estado:** `TaskListScreen` recoge `state` pero `items` sigue usando `viewModel.readAll()`. Además, el `MutableStateFlow` se crea una sola vez, así que la lista no se actualiza al crear una tarea. Todo indica que se termina en la parte 2. Tampoco se ve la navegación de vuelta tras "Save".
- **`Modifier.Companion`:** `TaskListScreen` usa `Modifier.Companion` como valor por defecto y `TaskCreateScreen` usa `Modifier`. Son equivalentes.
- **`Route(val route: String)`:** las rutas tipadas llevan además el parámetro de texto. Es una mezcla poco habitual. Los `fun serializer()` que se ven son plegados del IDE, no código escrito.
- **Partes ilegibles:** el contenido exacto de `composable<Route.TaskCreate>` en img001 (en img004 se ve como `TaskCreateScreen()`) y la línea de `consumeWindowInsets` en img078.
