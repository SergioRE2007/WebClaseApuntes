## Parámetros de ruta: materiales/:id

<DeClase fecha="19/11" nota="solo en el enunciado (apartados 5.1 y 5.2)" />

Esto es lo que pone el documento de la actividad:

```ts title="Del enunciado: la ruta, dentro de children de aula"
{ path: 'materiales/:id', component: DetalleMaterialComponent }
```

```html title="Del enunciado: materiales.component.html"
<h3>Materiales disponibles</h3>
<a [routerLink]="['/aula/materiales', 1]">Material 1</a>
<a [routerLink]="['/aula/materiales', 7]">Material 7</a>
```

- Los dos puntos de `:id` indican un **segmento dinámico**: `/aula/materiales/1`, `/aula/materiales/7`… van todos al mismo componente.
- `[routerLink]` con un **array de segmentos** monta la URL: `['/aula/materiales', 7]` es `/aula/materiales/7`. Así no hay que concatenar textos.
- En una captura se lee `['/aula/materiales', 5]` con el texto "Material 1" <Dudoso nota="En las demás capturas se repiten el 1 y el 7." />.
- Orden: si dentro de `children` hubiera una ruta `materiales/nuevo`, tendría que ir **antes** de `materiales/:id`, porque si no `nuevo` se tomaría como un id.

## Leer el parámetro: snapshot u observable <NoDadoEnClase inline />

El parámetro se lee con **`ActivatedRoute`**, que representa la ruta que ha activado el componente. Hay dos formas, y la solución desplegada enseñaba las dos a la vez para que se viera la diferencia:

```ts title="pages/aula/detalle-material/detalle-material.component.ts"
import { Component, OnInit, inject } from '@angular/core';
import { ActivatedRoute, RouterLink } from '@angular/router';

@Component({
  selector: 'app-detalle-material',
  imports: [RouterLink],
  templateUrl: './detalle-material.component.html',
})
export class DetalleMaterialComponent implements OnInit {
  private route = inject(ActivatedRoute);

  protected idSnapshot = '';
  protected idObservable = '';

  ngOnInit(): void {
    // Una foto de la ruta en el momento de crear el componente
    this.idSnapshot = this.route.snapshot.paramMap.get('id') ?? '';

    // Un Observable que avisa cada vez que cambia el parámetro
    this.route.paramMap.subscribe(params => {
      this.idObservable = params.get('id') ?? '';
    });
  }
}
```

```html title="detalle-material.component.html"
<p>Material id snapshot: {{ idSnapshot }}</p>
<p>Material id observable: {{ idObservable }}</p>
<a [routerLink]="['/aula/materiales', 7]">Ir al material 7</a>
```

| | `route.snapshot.paramMap.get('id')` | `route.paramMap.subscribe(...)` |
| --- | --- | --- |
| Qué es | Una foto del momento en que se creó el componente | Un `Observable` que emite cada vez que cambia |
| Si se navega a otro id sin salir del componente | Se queda con el valor viejo | Se actualiza |
| Cuándo usarlo | Cuando siempre se llega al detalle desde fuera (desde el listado) | Cuando se puede saltar de un detalle a otro |

- Los parámetros llegan siempre como **texto**: para pedir el material a una API, `Number(params.get('id'))`.
- Según la documentación de Angular, no hace falta desuscribirse de `paramMap` ni de los demás observables de `ActivatedRoute`: el router los limpia junto con el componente cuando lo destruye.
- Para encadenar el parámetro con una petición HTTP, la guía usa `switchMap`: `this.route.paramMap.pipe(switchMap(p => this.service.getMaterial(Number(p.get('id')))))`. Lo tienes explicado en [RxJS y gestión de errores](/docs/2-dam/acceso-a-datos/angular-avanzado/rxjs-y-errores).

## Query params

<DeClase fecha="19/11" nota="solo en el enunciado y en la solución desplegada" />

Los *query params* son la parte de la URL después de `?`. A diferencia de `:id`, son **opcionales** y no cambian qué ruta coincide: `/aula/materiales` y `/aula/materiales?orden=asc` van al mismo componente. La solución tenía dos enlaces, "Materiales (asc)" y "Materiales (desc)", y mostraba "Material order asc" (snapshot) y "Material order observable asc".

```html title="Enlaces con query params"
<a [routerLink]="['/aula/materiales']" [queryParams]="{ orden: 'asc' }">Materiales (asc)</a>
<a [routerLink]="['/aula/materiales']" [queryParams]="{ orden: 'desc' }">Materiales (desc)</a>
```

```ts title="materiales.component.ts (leerlos)"
private route = inject(ActivatedRoute);
protected orden = 'asc';

ngOnInit(): void {
  this.route.queryParamMap.subscribe(q => {
    this.orden = q.get('orden') ?? 'asc';
  });
}
```

Desde código: `this.router.navigate(['/aula/materiales'], { queryParams: { orden: 'desc' } })`.

| Tipo | Ejemplo | Para qué |
| --- | --- | --- |
| Parámetro de ruta | `/aula/materiales/7` | Identificar el recurso: sin él, la ruta no tiene sentido |
| *Query param* | `/aula/materiales?orden=asc` | Opciones y filtros: orden, búsqueda, página… |

Es justo lo que necesitas para un listado con filtros: el criterio en la URL hace que se pueda recargar o compartir la búsqueda.

## Comodín ** y orden de las rutas

<DeClase fecha="19/11" nota="lista de tareas del enunciado" />

La fase de redirecciones del enunciado pedía: `routerLinkActive` en el menú, `/` → `/inicio`, `/portal` → `/aula`, una ruta `**` que muestre `NoEncontradoComponent` y **las redirecciones antes del comodín**.

```ts title="app.routes.ts (final de la lista)"
  { path: 'portal', redirectTo: '/aula', pathMatch: 'full' },
  { path: 'ayuda', component: AyudaComponent },
  { path: '**', component: NoEncontradoComponent }
];
```

- `**` coincide con **cualquier** URL. Como el router usa la primera ruta que coincide (*first-match-wins*), el comodín va siempre el último.
- Sin comodín, una URL que no existe hace fallar la navegación con `NG04002: Cannot match any routes`.
- La guía también enseña a redirigir en vez de mostrar una página: `{ path: '**', redirectTo: 'products' }`.

## Lazy loading de rutas con loadChildren

<DeClase fecha="19/11" nota="Fase VI del enunciado, vista de pasada" />

`loadComponent` (que sí salió el 27/10) retrasa la carga de **un** componente. `loadChildren` retrasa la de **un grupo de rutas entero**: todo el Aula, con sus hijas, en un fichero aparte que solo se descarga al entrar en `/aula`.

</NoSeVio>

  <Tab value="aula.routes.ts">

```ts title="src/app/pages/aula/aula.routes.ts"
import { Routes } from '@angular/router';
import { AulaComponent } from './aula.component';
import { MaterialesComponent } from './materiales/materiales.component';
import { DetalleMaterialComponent } from './detalle-material/detalle-material.component';
import { AvisosComponent } from './avisos/avisos.component';

export const AULA_ROUTES: Routes = [
  {
    path: '',
    component: AulaComponent,
    children: [
      { path: '', redirectTo: 'materiales', pathMatch: 'full' },
      { path: 'materiales', component: MaterialesComponent },
      { path: 'materiales/:id', component: DetalleMaterialComponent },
      { path: 'avisos', component: AvisosComponent },
    ],
  },
];
```

  </Tab>
  <Tab value="app.routes.ts">

```ts title="src/app/app.routes.ts"
export const routes: Routes = [
  { path: '', redirectTo: '/inicio', pathMatch: 'full' },
  { path: 'inicio', component: InicioComponent },
  {
    path: 'aula',
    loadChildren: () => import('./pages/aula/aula.routes').then(m => m.AULA_ROUTES),
  },
  { path: 'ayuda', component: AyudaComponent },
  { path: '**', component: NoEncontradoComponent },
];
```

  </Tab>

- `app.routes.ts` ya no importa `AulaComponent` ni sus hijas: si las importara, entrarían en el JavaScript inicial y no habría carga perezosa.
- Dentro de `AULA_ROUTES` los `path` son relativos a `aula`: el `''` es `/aula`.
- **Para comprobarlo** (lo pide la actividad): F12 → **Network**, recarga en `/inicio` y entra en Aula. La primera vez se descarga un fichero `chunk-XXXX.js`; las siguientes, no.

## Guards: quién puede entrar y salir <NoDadoEnClase inline />

Un *guard* es una función que el router ejecuta antes de entrar en una ruta (o de salir de ella) y que decide si se puede. Se generan con `ng generate guard <nombre>`.

| Guard | Pregunta |
| --- | --- |
| `CanActivate` | ¿Se puede entrar en esta ruta? |
| `CanActivateChild` | ¿Se puede entrar en sus hijas? |
| `CanDeactivate` | ¿Se puede salir de aquí? |
| `CanMatch` | ¿Esta ruta cuenta siquiera? (útil con lazy loading: si dice que no, ni se descarga) |

<Tabs items={['CanActivate', 'CanDeactivate']}>
  <Tab value="CanActivate">

```ts title="src/app/auth.guard.ts"
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { AuthService } from './services/auth.service';

export const authGuard: CanActivateFn = () => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.isLoggedIn()) {
    return true;
  }
  return router.parseUrl('/login');
};
```

```ts title="app.routes.ts"
{ path: 'mis-pedidos', component: MisPedidosComponent, canActivate: [authGuard] }
```

  Si hay sesión, devuelve `true` y se entra. Si no, devuelve un `UrlTree` (`parseUrl`): el router cancela la navegación y va a `/login`. El `AuthService` con `isLoggedIn` lo tienes en [Listado con filtros, paginación y token](/docs/2-dam/acceso-a-datos/angular-avanzado/listado-filtros-y-token).

  </Tab>
  <Tab value="CanDeactivate">

```ts title="src/app/salir.guard.ts"
import { CanDeactivateFn } from '@angular/router';
import { NuevoJuegoComponent } from './pages/nuevo-juego/nuevo-juego.component';

export const salirGuard: CanDeactivateFn<NuevoJuegoComponent> = (component) => {
  if (!component.formGroup.dirty) {
    return true;
  }
  return confirm('Tienes cambios sin guardar. ¿Seguro que quieres salir?');
};
```

```ts title="app.routes.ts"
{ path: 'juegos/nuevo', component: NuevoJuegoComponent, canDeactivate: [salirGuard] }
```

  El guard recibe el componente del que se sale, así que puede mirar su estado. `confirm()` es el cuadro del navegador con Aceptar y Cancelar: es lo que usan las guías de Routing (en el carrito) y de Formularios, siempre dentro de un `CanDeactivate`.

  </Tab>
</Tabs>

<Callout type="warn" title="Un guard no es seguridad">
  El guard solo esconde pantallas en el navegador; cualquiera puede saltárselo. Lo que de verdad protege los datos es que **la API** compruebe el token en cada petición.
</Callout>

## Resolvers y withComponentInputBinding <NoDadoEnClase inline />

Un **resolver** carga datos **antes** de activar la ruta: el componente nace con los datos ya listos.

```ts title="src/app/material.resolver.ts"
import { inject } from '@angular/core';
import { ResolveFn } from '@angular/router';
import { Material, MaterialService } from './services/material.service';

export const materialResolver: ResolveFn<Material> = (route) => {
  return inject(MaterialService).getMaterial(Number(route.paramMap.get('id')));
};
```

```ts title="app.routes.ts"
{ path: 'materiales/:id', component: DetalleMaterialComponent, resolve: { material: materialResolver } }
```

Con **`withComponentInputBinding()`** el router pasa los parámetros, los *query params* y los datos resueltos directamente a los `input()` del componente que se llamen igual. Te ahorras `ActivatedRoute`:

```ts title="app.config.ts"
provideRouter(routes, withComponentInputBinding())
```

```ts title="detalle-material.component.ts (con inputs)"
export class DetalleMaterialComponent {
  id = input<string>();          // el :id de la URL
  orden = input<string>();       // ?orden=asc
  material = input<Material>();  // lo que devuelve el resolver con la clave material
}
```

Como son signals, se leen con paréntesis (`this.id()`) y se actualizan solos aunque el componente se reutilice.

<Ejercicio titulo="Detalle de un juego por URL" dificultad="media">
  En `proj-game`, crea una ruta `juegos/:id` con un `DetalleJuegoComponent` que lea el id de la URL y pida el juego con `gameService.getGameById(id)`. Haz que funcione también si desde el detalle se navega a otro juego.

  <Pista>Como se puede saltar de un detalle a otro, no te vale el snapshot: suscríbete a `paramMap`.</Pista>
  <Pista>El id llega como texto: `Number(params.get('id'))`.</Pista>

  <Solucion>

```ts
export class DetalleJuegoComponent implements OnInit {
  private route = inject(ActivatedRoute);
  private gameService = inject(GameService);
  protected game = signal<Game | undefined>(undefined);

  ngOnInit(): void {
    this.route.paramMap.subscribe(params => {
      const id = Number(params.get('id'));
      this.gameService.getGameById(id).subscribe(game => this.game.set(game));
    });
  }
}
```

```html
@if (game(); as g) {
  <h2>{{ g.title }}</h2>
  <p>{{ g.genre }} · {{ g.platform }} · {{ g.price }} €</p>
} @else {
  <p>Cargando...</p>
}
```

  Con `switchMap` (de RxJS) se evita la suscripción dentro de otra suscripción y se cancela la petición anterior si cambias de juego rápido: `this.route.paramMap.pipe(switchMap(p => this.gameService.getGameById(Number(p.get('id'))))).subscribe(g => this.game.set(g))`.

  </Solucion>
</Ejercicio>
