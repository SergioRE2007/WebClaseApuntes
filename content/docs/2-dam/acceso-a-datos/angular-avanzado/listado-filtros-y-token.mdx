## Qué piden y qué se dio

| Requisito de la web | Estado | Dónde se dio | Qué falta |
| --- | --- | --- | --- |
| Búsqueda, filtro y orden | A medias | 12/11: buscar por id y paginar con JSON Server | Mandar los criterios a vuestra API |
| Paginación | A medias | 12/11: `_page`, `_limit` y `observe: 'response'` | Lo mismo, con el total que devuelva vuestra API |
| Estados de carga, vacío y error | A medias | 27/10: las plantillas las generó la IA de Cursor | Los cuatro estados, hechos a mano |
| Borrar con confirmación | A medias | Solo en la guía: `confirm()` dentro de un `CanDeactivate` | Un botón Borrar que pregunte antes |
| HTTP solo en servicios | Dado | 27/10 y 28/10 | Nada |

La idea de fondo: **Angular solo manda los criterios y pinta lo que devuelve la API**. Quien busca, filtra, ordena y pagina es el backend (con Prisma), no el navegador. En `proj-game` lo hacía JSON Server; en tu proyecto lo hace tu API de Node.

## Los tipos y el servicio

Los ejemplos usan una tienda con **categorías** y **productos**. Cambia los nombres por los de tu proyecto. La respuesta del backend tiene esta forma (la de [Listado con búsqueda, filtro, orden y paginación](/docs/2-dam/apis/backend-proyecto/listado-paginado), en los apuntes de Node):

```json title="GET /api/productos?page=1&limit=10"
{
  "items": [
    { "id": 1, "nombre": "Ratón inalámbrico", "precio": "24.5", "stock": 30, "categoria": { "id": 1, "nombre": "Periféricos" } }
  ],
  "total": 3,
  "page": 1,
  "limit": 10,
  "totalPages": 1
}
```

El precio llega como texto (`"24.5"`) porque Prisma manda los `Decimal` así para no perder decimales. Por eso en el modelo de Angular es `string`.

```ts title="src/app/services/product.service.ts"
import { Injectable, inject } from '@angular/core';
import { HttpClient, HttpParams } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface Categoria {
  id: number;
  nombre: string;
}

export interface Producto {
  id: number;
  nombre: string;
  precio: string;
  stock: number;
  categoria: Categoria;
}

export interface Pagina<T> {
  items: T[];
  total: number;
  page: number;
  limit: number;
  totalPages: number;
}

export interface FiltroProductos {
  q?: string;
  categoriaId?: number;
  orden?: 'nombre' | 'precio' | 'createdAt';
  dir?: 'asc' | 'desc';
  page?: number;
  limit?: number;
}

@Injectable({ providedIn: 'root' })
export class ProductService {
  private http = inject(HttpClient);
  private apiUrl = 'http://localhost:3000/api/productos';

  getProductos(filtro: FiltroProductos): Observable<Pagina<Producto>> {
    let params = new HttpParams();
    for (const [clave, valor] of Object.entries(filtro)) {
      if (valor !== undefined && valor !== '') {
        params = params.set(clave, valor);
      }
    }
    return this.http.get<Pagina<Producto>>(this.apiUrl, { params });
  }

  deleteProducto(id: number): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}
```

- **`Pagina<T>`** es genérica, como una clase genérica de Java: vale para cualquier listado paginado. Tiene la misma forma que devuelve el backend.
- `apiUrl` va dentro del servicio, como lo hace el profesor en clase.
- Se saltan los criterios vacíos para no mandar `?q=&categoriaId=`.
- **`HttpParams`** monta la parte `?q=...&page=...` y codifica los espacios y las tildes. Comparado con lo de `proj-game` (concatenar `?_page=${pag}&_limit=${tamPage}` a mano), es más seguro: un texto con `&` o con espacios no rompe la URL.

<Comparar titulo="HttpParams es inmutable">
  <Lado tipo="evitar" titulo="Se pierde todo">

```ts
const params = new HttpParams();
params.set('q', 'teclado');
params.set('page', 2);
// params sigue vacío
```

`set` **no cambia** el objeto: devuelve uno nuevo, que aquí se tira. La petición sale sin filtros.

  </Lado>
  <Lado tipo="bien" titulo="Bien">

```ts
let params = new HttpParams();
params = params.set('q', 'teclado');
params = params.set('page', 2);
// ?q=teclado&page=2
```

Cada `set` devuelve un `HttpParams` nuevo y se guarda en la misma variable. También se pueden encadenar: `new HttpParams().set('q', 'teclado').set('page', 2)`.

  </Lado>
</Comparar>

## El componente

<Recorrido
  titulo="src/app/pages/productos/productos.component.ts"
  lenguaje="typescript"
  codigo={`@Component({
  selector: 'app-productos',
  imports: [ReactiveFormsModule],
  templateUrl: './productos.component.html',
})
export class ProductosComponent implements OnInit {
  private productService = inject(ProductService);

  protected buscador = new FormControl('', { nonNullable: true });
  protected orden = new FormControl<'nombre' | 'precio' | 'createdAt'>('createdAt', { nonNullable: true });

  protected productos = signal<Producto[]>([]);
  protected total = signal(0);
  protected page = signal(1);
  protected totalPages = signal(1);
  protected loading = signal(false);
  protected error = signal('');

  ngOnInit(): void {
    this.cargar();
  }

  protected cargar(): void {
    this.loading.set(true);
    this.error.set('');
    this.productService
      .getProductos({
        q: this.buscador.value,
        orden: this.orden.value,
        dir: 'asc',
        page: this.page(),
        limit: 10,
      })
      .subscribe({
        next: (pagina) => {
          this.productos.set(pagina.items);
          this.total.set(pagina.total);
          this.totalPages.set(Math.max(1, pagina.totalPages));
          this.loading.set(false);
        },
        error: () => {
          this.error.set('No se han podido cargar los productos');
          this.loading.set(false);
        },
      });
  }

  protected buscar(): void {
    this.page.set(1);
    this.cargar();
  }

  protected irAPagina(pagina: number): void {
    this.page.set(pagina);
    this.cargar();
  }

  protected borrar(producto: Producto): void {
    if (!confirm(\`¿Borrar "\${producto.nombre}"?\`)) return;
    this.productService.deleteProducto(producto.id).subscribe({
      next: () => this.cargar(),
      error: () => this.error.set('No se ha podido borrar'),
    });
  }
}`}

| Estado | Cuándo | Qué se ve |
| --- | --- | --- |
| Cargando | `loading()` es `true` | "Cargando…" |
| Error | `error()` tiene texto | El mensaje y un botón Reintentar |
| Vacío | La lista llega vacía (`@empty` del `@for`) | "No hay productos con esos filtros." |
| Con datos | El resto | La lista y la paginación |

- `@empty` es la rama del `@for` que se pinta cuando la lista no tiene elementos.
- `(keyup.enter)` es un evento de Angular que solo salta con la tecla Intro.
- Todos los signals se leen con paréntesis: `{{ total() }}`, no `{{ total }}`.

Si quieres que busque **mientras se escribe**, sin pulsar el botón, en el constructor:

```ts
constructor() {
  this.buscador.valueChanges
    .pipe(debounceTime(300), takeUntilDestroyed())
    .subscribe(() => this.buscar());
}
```

`debounceTime(300)` espera a que se dejen de pulsar teclas para no hacer una petición por letra. Lo tienes explicado en [RxJS y gestión de errores](/docs/2-dam/acceso-a-datos/angular-avanzado/rxjs-y-errores).

## Guardar el token aunque se recargue la página

En la guía de HTTP, el token de la sesión vive solo en un signal: al recargar (F5) se pierde y hay que volver a iniciar sesión. Para que no pase, se guarda también en **`localStorage`**, un almacén del navegador que no se borra al recargar:

```ts title="src/app/services/auth.service.ts"
import { Injectable, computed, inject, signal } from '@angular/core';
import { HttpInterceptorFn } from '@angular/common/http';

@Injectable({ providedIn: 'root' })
export class AuthService {
  private readonly clave = 'token';
  accessToken = signal(localStorage.getItem(this.clave) ?? '');
  isLoggedIn = computed(() => this.accessToken() !== '');

  guardarToken(token: string): void {
    localStorage.setItem(this.clave, token);
    this.accessToken.set(token);
  }

  logout(): void {
    localStorage.removeItem(this.clave);
    this.accessToken.set('');
  }
}

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).accessToken();
  if (!token) return next(req);
  return next(req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }));
};
```

```ts title="src/app/app.config.ts"
import { provideHttpClient, withInterceptors } from '@angular/common/http';
import { authInterceptor } from './services/auth.service';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes),
    provideHttpClient(withInterceptors([authInterceptor])),
  ],
};
```

- **Al arrancar**, el signal empieza con lo que haya en `localStorage`. Si había sesión, sigue abierta.
- `isLoggedIn` es un `computed`: siempre está de acuerdo con el token, sin actualizarlo a mano. Es lo que usaría un `authGuard` (lo tienes en [Parámetros, guards y lazy loading](/docs/2-dam/acceso-a-datos/angular-avanzado/rutas-parametros-guards)).
- Tras el login, el componente llama a `authService.guardarToken(respuesta.token)`.
- El **interceptor** es el de la guía de HTTP (`8_HTTP.md`): una función por la que pasan **todas** las peticiones de `HttpClient`. Si hay token, añade la cabecera `Authorization: Bearer ...`, que es lo que espera el middleware de tu API.
- `req.clone(...)`: las peticiones son **inmutables**, como `HttpParams`. No se modifican; se copian con la cabecera nueva.
- `localStorage` lo puede leer cualquier JavaScript de la página. Para un proyecto de clase vale; en una app real se usan cookies `httpOnly`.
- La parte del backend (CORS para tu web y el middleware que comprueba el token) está en [CORS y rutas protegidas](/docs/2-dam/apis/backend-proyecto/cors-y-token).
