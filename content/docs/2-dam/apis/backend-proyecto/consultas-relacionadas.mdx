Los requisitos piden "información relacionada entre entidades" y que las relaciones "tengan una repercusión real en la interfaz" (§5). Es decir: no basta con tener `categoriaId` en la tabla, la API tiene que **usar** la relación (enseñar la categoría de cada producto, los productos de una categoría, cuántos hay…).

<Callout type="idea" title="Lo que vas a aprender">
  - Qué consultas de Prisma se vieron en clase.
  - `include` para traer los relacionados y `select` para elegir campos.
  - `_count` para contar sin traer.
  - `where` con criterios y con relaciones (`some`, `none`, `every`).
  - Devolver `404` cuando no existe.
</Callout>

## Lo que se vio en clase

<DeClase fecha="27/10" proyecto="node-server-26-27" nota="módulo users, v0.4.0" />

En el servicio de usuarios del profesor salen `findMany` con `select` y `orderBy`, `findUnique` con `where`, y `create`, `update` y `delete`. El `select` está en todas las funciones para **no devolver nunca `passwordHash`**:

```ts title="src/modules/users/users.service.ts (fragmento de clase)"
export async function findUserById(id: number) {
  return prisma.user.findUnique({
    where: { id },
    select: { id: true, email: true, name: true, createdAt: true }
  });
}

export async function listUsers() {
  return prisma.user.findMany({
    select: { id: true, email: true, name: true, createdAt: true },
    orderBy: { id: 'asc' }
  });
}
```

- `findUnique` busca por un campo `@id` o `@unique` y devuelve el objeto o **`null`** si no existe.
- `select` dice qué columnas vuelven. Lo que no está en el `select` no sale en el JSON.
- `orderBy` ordena: `'asc'` o `'desc'`.

Todas las consultas que se vieron son sobre `User`, sin relaciones: el módulo `media` (el único con una clave ajena) no se llegó a ver. Así que hasta aquí llegó la clase.

## include: la fila y sus relacionados <NoDadoEnClase inline />

<NoDadoEnClase>
  `include`, `select` dentro de una relación, `_count`, los operadores del `where` (`lte`, `gt`, `OR`…), los filtros por relación (`some`, `none`, `every`) y el controlador con `404` de esta página no se han dado en clase.
</NoDadoEnClase>

`include` trae la fila **y además** sus relacionados, enteros. Es lo que en SQL harías con un `JOIN`:

```ts title="src/modules/categorias/categorias.service.ts"
import { prisma } from '../../config/db.js';

export function obtenerCategoriaConProductos(id: number) {
  return prisma.categoria.findUnique({
    where: { id },
    include: { productos: { orderBy: { nombre: 'asc' } } },
  });
}
```

```json title="Respuesta de GET /api/categorias/1"
{
  "id": 1,
  "nombre": "Periféricos",
  "productos": [
    { "id": 2, "nombre": "Ratón inalámbrico", "descripcion": null, "precio": "24.5", "stock": 30, "categoriaId": 1, "createdAt": "2026-12-09T10:00:00.000Z" },
    { "id": 1, "nombre": "Teclado mecánico", "descripcion": null, "precio": "59.9", "stock": 12, "categoriaId": 1, "createdAt": "2026-12-09T10:00:00.000Z" }
  ]
}
```

Dentro del `include` puedes ordenar, filtrar (`where`) o limitar (`take`) los relacionados, como aquí con `orderBy`. Por defecto Prisma 6 lo resuelve con dos consultas (una para la categoría y otra para sus productos), pero el resultado es el mismo que con un `JOIN`.

## select: elegir los campos, también de la relación <NoDadoEnClase inline />

`select` elige qué campos vuelven. Dentro de un `select` también se puede meter una relación con su propio `select`:

```ts title="productos.service.ts"
export function listarProductosResumen() {
  return prisma.producto.findMany({
    select: {
      id: true,
      nombre: true,
      precio: true,
      categoria: { select: { id: true, nombre: true } },
    },
  });
}
```

```json title="Cada producto queda así"
{ "id": 1, "nombre": "Teclado mecánico", "precio": "59.9", "categoria": { "id": 1, "nombre": "Periféricos" } }
```

<Comparar titulo="include frente a select">
  <Lado titulo="include">

```ts
prisma.producto.findUnique({
  where: { id: 1 },
  include: { categoria: true },
});
```

Devuelve **todos** los campos del producto y **además** la categoría entera. Cómodo, pero manda cosas que quizá no necesitas.

  </Lado>
  <Lado titulo="select">

```ts
prisma.producto.findUnique({
  where: { id: 1 },
  select: {
    nombre: true,
    precio: true,
    categoria: { select: { nombre: true } },
  },
});
```

Devuelve **solo** lo que pides. Es lo que cumple el requisito de "selección de campos" y lo que usó el profesor para no devolver `passwordHash`.

  </Lado>
</Comparar>

<Callout type="warn" title="include y select no van juntos en el mismo nivel">
  `findMany({ include: {...}, select: {...} })` da un error de validación de Prisma. Elige uno: si quieres elegir campos y traer una relación, mete la relación **dentro** del `select`, como en el ejemplo de arriba.
</Callout>

## _count: contar sin traer <NoDadoEnClase inline />

`_count` cuenta los relacionados sin traerlos. Sirve, por ejemplo, para un menú que enseñe "Periféricos (2)":

```ts title="categorias.service.ts"
export function contarProductosPorCategoria() {
  return prisma.categoria.findMany({
    select: { id: true, nombre: true, _count: { select: { productos: true } } },
  });
}
```

```json title="Respuesta"
[
  { "id": 1, "nombre": "Periféricos", "_count": { "productos": 2 } },
  { "id": 2, "nombre": "Monitores", "_count": { "productos": 1 } }
]
```

Sale mucho más barato que traer todos los productos para luego contarlos en Angular.

## where: consultas por criterios <NoDadoEnClase inline />

Los requisitos también piden "consultas por diferentes criterios". El `where` de Prisma admite operadores para cada tipo de campo:

```ts title="productos.service.ts"
// Baratos y con stock
prisma.producto.findMany({
  where: { precio: { lte: 50 }, stock: { gt: 0 } },
});

// De una categoría, buscando por el nombre de la categoría (relación 1)
prisma.producto.findMany({
  where: { categoria: { nombre: 'Periféricos' } },
});

// Categorías con algún producto agotado (relación N)
prisma.categoria.findMany({
  where: { productos: { some: { stock: 0 } } },
});

// Varios criterios con OR
prisma.producto.findMany({
  where: { OR: [{ stock: 0 }, { precio: { gte: 300 } }] },
});
```

| Operador | Significa |
| --- | --- |
| `equals` (o el valor a secas) | Igual |
| `not` | Distinto |
| `lt`, `lte`, `gt`, `gte` | Menor, menor o igual, mayor, mayor o igual |
| `in`, `notIn` | Está (o no) en una lista: `{ id: { in: [1, 2, 3] } }` |
| `contains`, `startsWith`, `endsWith` | Texto que contiene, empieza o acaba por (con `mode: 'insensitive'` no distingue mayúsculas) |
| `AND`, `OR`, `NOT` | Combinar condiciones |
| `some`, `every`, `none` | En una relación N: algún hijo, todos los hijos o ningún hijo cumple |

## Si no existe: 404 <NoDadoEnClase inline />

`findUnique` devuelve `null` si no encuentra nada, y eso no es un error de Prisma: tienes que comprobarlo tú en el controlador. Siguiendo el estilo de los controladores de clase (comprobar el id con `Number` e `isNaN`). Del `getUserCtrl` de clase solo se vio ese principio; cómo respondía cuando no encontraba el usuario no se llegó a ver, así que este final no es del profesor:

```ts title="categorias.controller.ts"
import type { Request, Response } from 'express';
import { obtenerCategoriaConProductos } from './categorias.service.js';

export async function obtenerCategoriaCtrl(req: Request, res: Response) {
  const id = Number(req.params.id);
  if (isNaN(id)) {
    return res.status(400).json({ message: 'ID inválido' });
  }
  const categoria = await obtenerCategoriaConProductos(id);
  if (!categoria) {
    return res.status(404).json({ message: 'Categoría no encontrada' });
  }
  res.json(categoria);
}
```

<Callout title="P2025 frente a null">
  En clase, `updateUserCtrl` traducía el error `P2025` a `404`: lo lanzan `update` y `delete` cuando no encuentran la fila. `findUnique` y `findFirst` **no** lanzan nada: devuelven `null`. Por eso aquí se comprueba con un `if`.
</Callout>

<Ejercicio titulo="Página de detalle de un producto" dificultad="facil">
  Escribe la función de servicio `obtenerProducto(id)` que devuelva el producto con `id`, `nombre`, `descripcion`, `precio`, `stock` y, de su categoría, solo `id` y `nombre`. Después, el controlador `GET /api/productos/:id` con `400` si el id no es un número y `404` si no existe.

  <Pista>`findUnique` con `where` y un `select` que tenga dentro `categoria: { select: {...} }`.</Pista>

  <Solucion>

```ts title="productos.service.ts"
export function obtenerProducto(id: number) {
  return prisma.producto.findUnique({
    where: { id },
    select: {
      id: true,
      nombre: true,
      descripcion: true,
      precio: true,
      stock: true,
      categoria: { select: { id: true, nombre: true } },
    },
  });
}
```

```ts title="productos.controller.ts"
export async function obtenerProductoCtrl(req: Request, res: Response) {
  const id = Number(req.params.id);
  if (isNaN(id)) {
    return res.status(400).json({ message: 'ID inválido' });
  }
  const producto = await obtenerProducto(id);
  if (!producto) {
    return res.status(404).json({ message: 'Producto no encontrado' });
  }
  res.json(producto);
}
```

</Solucion>
</Ejercicio>
