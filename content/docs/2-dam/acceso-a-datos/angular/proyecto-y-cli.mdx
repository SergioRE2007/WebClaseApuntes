**Angular** es un *framework* de Google para hacer aplicaciones web de una sola página (SPA): el navegador descarga una vez la aplicación y, a partir de ahí, Angular cambia la pantalla sin recargar la página. Se programa en **TypeScript**, que es JavaScript con tipos, y se maneja casi todo desde la terminal con el **Angular CLI** (`ng`).

En clase se usó **Angular 19** (en DevTools sale `ng-version="19.2.25"` y en `package.json` los paquetes van con `^19.2.0`).

<Callout type="idea" title="Lo que vas a aprender">
  - Crear un proyecto con `ng new` y entender cada archivo que genera.
  - Cómo arranca una aplicación: de `index.html` a `AppComponent`.
  - Arrancar el servidor de desarrollo con `ng serve -o` y los scripts de `package.json`.
  - Generar componentes, servicios e interfaces con `ng generate`.
  - Leer los rangos de versiones (`^` y `~`) y distinguir `dependencies` de `devDependencies`.
</Callout>

## Crear un proyecto

<DeClase fecha="28/10" proyecto="proj-game" nota="el proyecto proj-lamp del 14/10 ya venía creado" />

```bash title="Terminal"
ng new proj-game
```

El CLI hace dos preguntas. En clase se respondió así:

| Pregunta | Respuesta |
| --- | --- |
| Formato de estilos (*stylesheet format*) | **CSS** |
| ¿Activar SSR y SSG (renderizado en el servidor)? | **No** |

Crea la carpeta, instala las dependencias con npm e inicializa un repositorio de Git. Al abrirlo en VS Code sobre WSL puede salir el aviso de **Restricted Mode**: hay que pulsar "Trust Folder & Continue" para poder usar la terminal.

| Archivo | Para qué sirve |
| --- | --- |
| `src/index.html` | La única página HTML. Tiene `<base href="/">` y la etiqueta `<app-root>`, donde se monta la aplicación. |
| `src/main.ts` | El punto de entrada: arranca la aplicación con `AppComponent` y la configuración de `app.config.ts`. |
| `src/styles.css` | Estilos **globales**: valen para toda la aplicación. |
| `src/app/app.component.*` | El componente raíz: clase (`.ts`), plantilla (`.html`), estilos (`.css`) y pruebas (`.spec.ts`). |
| `src/app/app.config.ts` | Los *providers* de toda la aplicación: el router, `HttpClient`… |
| `src/app/app.routes.ts` | La tabla de rutas (al crear el proyecto, vacía). |
| `package.json` | Dependencias y scripts de npm. |
| `angular.json` | Configuración del CLI: cómo se compila y se sirve el proyecto. |
| `tsconfig*.json` | Configuración de TypeScript (modo `strict`). |

Lo de `angular.json` y los tres `tsconfig` está explicado a fondo en la Guía5 de ficheros de configuración del [repositorio de guías](https://github.com/hokahey007/guides-angular).

### El componente raíz

Así quedó `app.component.ts` en la clase de la lámpara, después de importar el hijo:

```ts title="src/app/app.component.ts"
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';
import { LamparaComponent } from './components/lampara/lampara.component';

@Component({
  selector: 'app-root',
  imports: [RouterOutlet, LamparaComponent],
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  title = 'proj-lamp';
}
```

Al crear el proyecto, `app.component.html` trae una plantilla de ejemplo muy larga (con un `<style>` y variables CSS en `:host`). En clase se borra entera y se escribe la plantilla propia.

  </Mensaje>

### Standalone: sin NgModule

En Angular 19 todos los componentes son **standalone**: cada uno dice en su array `imports` lo que usa su plantilla (otros componentes, `RouterOutlet`, pipes…). Ya no hace falta `NgModule`, que es lo que verás en tutoriales antiguos (`app.module.ts` con `declarations`).

<Callout type="info" title="standalone: true sobra en Angular 19">
  El 27/10 la IA de Cursor añadió `standalone: true` a varios componentes. No rompe nada, pero en Angular 19 ya es el valor por defecto.
</Callout>

## Arrancar el servidor de desarrollo

<DeClase fecha="14/10" proyecto="proj-lamp" />

```bash title="Terminal"
ng serve -o
```

- `ng serve` compila la aplicación y la sirve en `http://localhost:4200`. `-o` (`--open`) abre el navegador.
- Se queda **vigilando los archivos**: al guardar, recarga sola. Con HMR (*Hot Module Replacement*) los cambios de un componente o de un CSS se aplican sin recargar la página.
- Para pararlo, `Ctrl+C` en la terminal.

<Terminal titulo="bash — ~/proj-lamp">
{`$ ng serve -o
Component HMR has been enabled.
Initial total 138.84 kB
Application bundle generation complete.
  ➜  Local:   http://localhost:4200/
Component update sent to client(s).
Stylesheet update sent to client(s).`}
</Terminal>

Los mensajes del final salen cada vez que guardas un componente o una hoja de estilos.

### Los scripts de package.json

```json title="package.json (scripts)"
"scripts": {
  "ng": "ng",
  "start": "ng serve -o",
  "build": "ng build",
  "watch": "ng build --watch --configuration development",
  "test": "ng test"
}
```

| Comando | Qué hace |
| --- | --- |
| `npm start` | Ejecuta el script `start`. En clase se cambió de `ng serve` a `ng serve -o` para que abra el navegador. |
| `npm run build` | Compila para producción. El resultado queda en `dist/<proyecto>/browser`. |
| `npm run watch` | Compila en modo desarrollo cada vez que guardas, sin servidor. |
| `npm run test` | Lanza `ng test`: las pruebas `.spec.ts` con Karma y Jasmine, en el puerto 9876. |

En clase se probó un momento `"start": "ng serve -o --host 0.0.0.0 --port 4300"` (`--host 0.0.0.0` deja entrar desde otros equipos de la red y `--port` cambia el puerto), y se volvió a `ng serve -o`. VS Code también tiene un botón "Run Script" encima de cada script.

## Generar código con ng generate

<DeClase fecha="14/10, 27/10, 28/10" />

`ng generate` (abreviado `ng g`) crea los archivos con la estructura correcta. La ruta que le pasas es relativa a `src/app`.

| Comando | Crea |
| --- | --- |
| `ng g c components/lampara --skip-tests` | El componente `LamparaComponent` en `src/app/components/lampara/` (`.ts`, `.html` y `.css`, sin `.spec.ts`). |
| `ng g c pages/posts` | Un componente de página, con su `.spec.ts`. |
| `ng g s services/posts` | El servicio `PostsService` (`posts.service.ts` y `posts.service.spec.ts`). |
| `ng g i models/product` | La interfaz `Product` en `models/product.ts`. |
| `ng g interface interface/CRUD` | Lo mismo, escrito largo: la interfaz `CRUD` en `interface/crud.ts`. |

<Terminal titulo="bash — ~/proj-lamp">
{`$ ng g c --skip-tests components/lampara
CREATE src/app/components/lampara/lampara.component.css (0 bytes)
CREATE src/app/components/lampara/lampara.component.html (22 bytes)
CREATE src/app/components/lampara/lampara.component.ts (218 bytes)`}
</Terminal>

- `c` es *component*, `s` es *service* e `i` es *interface*. Las opciones pueden ir antes o después de la ruta.
- `--skip-tests` no genera el `.spec.ts`. En el autocompletado salen también `--skip-import` y `--skip-selector`. Ojo: algún enunciado pone `--skip-test`, pero la opción es `--skip-tests`.
- El componente nuevo trae la plantilla `<p>lampara works!</p>`, que es lo que ves en el navegador hasta que la cambias.

  El 27/10 se escribió `ng g pages/posts` y salió *"A collection and schematic is required during execution"*: falta decir **qué** se genera. Se arregla con `ng g c pages/posts`.
</Callout>

## Avisos y errores del compilador

El compilador de Angular revisa también las plantillas. Lo que salió en estas clases:

| Código | Qué significa | Cómo se arregla |
| --- | --- | --- |
| `TS-998113` | *"RouterOutlet is not used within the template of AppComponent"*: algo de `imports` no se usa en la plantilla. Es un **aviso**, no impide compilar. | Quitarlo de `imports`, o usarlo. |
| `NG1` | La plantilla usa una propiedad `private`. | Hacerla `protected` (ver [plantillas](/docs/2-dam/acceso-a-datos/angular/plantillas-y-binding)). |
| `TS2339` | *"Property 'x' does not exist on type..."*: por ejemplo, un parámetro del constructor sin `private`. | Ver [servicios](/docs/2-dam/acceso-a-datos/angular/servicios-e-inyeccion). |
| `TS2304` | *"Cannot find name 'PostsComponent'"*: se usa una clase sin importarla. | Añadir el `import` arriba del archivo. |

El **Angular Language Service** (la extensión de Angular para VS Code) marca estos errores en rojo mientras escribes y autocompleta las propiedades del componente dentro de la plantilla.

## package.json: dependencias y versiones

<DeClase fecha="28/10" proyecto="proj-game" />

- **`dependencies`**: lo que necesita la aplicación para funcionar (los paquetes `@angular/*`, `rxjs`, `zone.js`…).
- **`devDependencies`**: lo que solo hace falta para desarrollar y compilar (`@angular/cli`, `typescript`, Karma, Jasmine, `json-server`…). Se instalan con `npm install --save-dev paquete` (o `-D`).

### Rangos semver: `^` frente a `~`

Una versión tiene tres números: `MAYOR.MENOR.PARCHE`.

| Rango | Deja instalar | Ejemplo |
| --- | --- | --- |
| `^19.2.0` | Cualquier `19.x.y` igual o mayor que `19.2.0`. No pasa a la `20`. | `19.2.25` sí, `19.3.0` sí, `20.0.0` no. |
| `~5.7.2` | Solo parches: `5.7.x` igual o mayor que `5.7.2`. | `5.7.3` sí, `5.8.0` no. |
| `0.17.4` (sin símbolo) | Exactamente esa versión. | Solo `0.17.4`. |

`npm install --save-dev json-server@0.17.4` guarda `"^0.17.4"`, aunque le hayas pedido una versión exacta.

Al instalar paquetes, npm avisa a veces de vulnerabilidades y propone `npm audit fix`. En clase salieron 30. `npm audit fix --force` puede actualizar a versiones mayores y romper el proyecto, así que úsalo con cuidado.

  Con estas líneas de un `package.json`, di qué versiones se podrían instalar de cada paquete al hacer `npm install` en un equipo nuevo, y si cada uno es de `dependencies` o de `devDependencies`: `"rxjs": "~7.8.0"`, `"@angular/router": "^19.2.0"`, `"karma": "~6.4.0"`.

  <Pista>`~` solo deja cambiar el último número; `^`, los dos últimos.</Pista>

  <Solucion>

| Paquete | Versiones posibles | Sección |
| --- | --- | --- |
| `rxjs ~7.8.0` | `7.8.0` o un parche posterior (`7.8.x`) | `dependencies`: la aplicación lo usa al ejecutarse (los `Observable`). |
| `@angular/router ^19.2.0` | Cualquier `19.x.y` desde la `19.2.0` | `dependencies` |
| `karma ~6.4.0` | `6.4.x` desde la `6.4.0` | `devDependencies`: solo sirve para lanzar las pruebas. |

Para que todos tengáis **exactamente** las mismas versiones está `package-lock.json`, que se sube a Git, y `npm ci`, que instala justo lo que pone ese archivo.

  </Solucion>
