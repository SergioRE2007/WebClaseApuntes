## El Validador

`Validador.cs` tiene un delegado propio, `ValidarNumero`, y varios métodos estáticos con su misma firma (reciben un `int` y devuelven `bool`). Cada uno escribe su resultado en consola. Así quedó al final de la clase:

```csharp title="Validador.cs (18/11)"
using System;

public class Validador
{
    public delegate bool ValidarNumero(int x);

    /*Func<int, bool> ValidarNumero2;

    public delegate void DelegadoSinResultado(int x);
    Action<int, string, string, int> DelegadoSinResultado2;

    Predicate<int> ValidarNumero3;

    public delegate bool MiDelegado(int x, string str);
    Func<int, string, bool> MiDelegado2;*/

    public static void ImprimeNumero(int x)
    {
        Console.WriteLine($"El número ingresado es: {x}");
    }

    public static bool EsNegativo(int x)
    {
        bool resultado = x < 0;
        Console.WriteLine($"El resultado de la funcion EsNegativo para {x} es: {resultado}");
        return resultado;
    }

    public static bool EsPositivo(int x)
    {
        bool resultado = x > 0;
        Console.WriteLine($"El resultado de la funcion EsPositivo para {x} es: {resultado}");
        return resultado;
    }

    public static bool EsImpar(int x) => !EsPar(x);

    public static bool EsPar(int x)
    {
        bool resultado = x % 2 == 0;
        Console.WriteLine($"El resultado de la funcion EsPar para {x} es: {resultado}");
        return resultado;
    }

    public static bool MayorACero(int x)
    {
        bool resultado = x > 0;
        Console.WriteLine($"El resultado de la funcion MayorACero para {x} es: {resultado}");
        return resultado;
    }

    public static bool Ejecutar(ValidarNumero validate, int x)
    {
        bool resultado = true;
        foreach (ValidarNumero paso in validate.GetInvocationList())
        {
            resultado = resultado && paso(x);
        }
        if (resultado)
        {
            Console.WriteLine($"El numero {x} cumple con las validaciones");
        }
        else
        {
            Console.WriteLine($"El numero {x} NO cumple con las validaciones");
        }
        return resultado;
    }
}
```

El bloque comentado con `/* */` son las declaraciones que se probaron en la segunda mitad de la clase: lo tienes en [Func, Action y Predicate](/docs/2-dam/desarrollo-de-interfaces/csharp/func-action-predicate). `ImprimeNumero` no devuelve nada, así que **no encaja** con `ValidarNumero`: se escribió para hablar de `Action`.

## El programa que lo usa

`Program.cs` pide un número dentro de un `do/while` y repite **hasta que cumpla todas las validaciones**. Recórrelo:

  </Paso>

  </Paso>

## Por qué la primera versión mentía

Al empezar la clase, `Ejecutar` llamaba al delegado directamente. Con **-6** se escribían los tres resultados (False, True y True)… y salía *"El numero -6 cumple con las validaciones"*, aunque `EsPositivo` había dicho False.

<Comparar titulo="El método Ejecutar">
  <Lado tipo="evitar" titulo="Primera versión: engañosa">

```csharp
public static bool Ejecutar(ValidarNumero validate, int x)
{
    bool resultado = validate(x);
    if (resultado) { /* cumple */ } else { /* NO cumple */ }
    return resultado;
}
```

`validate(x)` ejecuta **todos** los métodos, pero un multicast solo devuelve lo del **último**. El último era el de "divisible por 3", y -6 lo es: True.

  </Lado>
  <Lado tipo="bien" titulo="Versión final de clase">

```csharp
public static bool Ejecutar(ValidarNumero validate, int x)
{
    bool resultado = true;
    foreach (ValidarNumero paso in validate.GetInvocationList())
    {
        resultado = resultado && paso(x);
    }
    // ... escribe si cumple o no
    return resultado;
}
```

Evalúa los métodos **uno a uno** y acumula con `&&`: solo es `true` si **todos** lo son.

  </Lado>
</Comparar>

Es lo mismo que pasaba con la calculadora del 09/11 (ver [Delegados](/docs/2-dam/desarrollo-de-interfaces/csharp/delegados#el-problema-del-valor-de-retorno)): para tener cada resultado hay que recorrer `GetInvocationList()`.

### Cómo se llegó a la versión final

1. Primero, dentro de `Ejecutar`, un `foreach` con `Console.WriteLine(del.ToString())`, solo para **ver** qué métodos llevaba el delegado.
2. Después se reescribió para evaluarlos uno a uno. Pasó por `resultado = false`, por `resultado = paso(x)` y por un error **CS0103** (se escribió `repaso` en vez de `paso`, un nombre que no existe).
3. Se quedó en `resultado = resultado && paso(x)`, con `resultado = true` al principio. La variable del bucle pasó a llamarse `paso`.

### El acumulador y el cortocircuito

- `resultado` **empieza en `true`**. Si empezara en `false`, `false && lo-que-sea` sería siempre `false` y ningún número cumpliría nunca.
- `&&` hace **cortocircuito**: si lo de la izquierda ya es `false`, no evalúa lo de la derecha. En cuanto un paso da False, `resultado` vale `false` y en las siguientes vueltas **ya no se llama** a `paso(x)`.

Por eso, con la versión final, -6 solo escribe la línea de `EsPositivo`: los demás métodos ni se ejecutan.

<NoDadoEnClase titulo="El orden de los operandos importa">
  Si escribieras `resultado = paso(x) && resultado;`, el método se llamaría **siempre** (está a la izquierda) y verías todos los mensajes. El resultado final sería el mismo, pero sin cortocircuito.
</NoDadoEnClase>

## Tres formas de escribir el método

Un delegado acepta cualquier método que encaje con su firma, se escriba como se escriba:

<Tabs items={['Con nombre', 'Método anónimo', 'Lambda de bloque', 'Lambda de expresión']}>
  <Tab value="Con nombre">

```csharp
validar += Validador.EsPar;
```

Un método normal, declarado en una clase. Se pasa su nombre sin paréntesis (en inglés, *method group*).

  </Tab>
  <Tab value="Método anónimo">

```csharp
validar += delegate (int numero)
{
    bool resultado = numero % 3 == 0;
    Console.WriteLine($"... divisible por 3: {resultado}");
    return resultado;
};
```

La palabra `delegate`, los parámetros y el cuerpo. Sin parámetros: `delegate () { ... }`.

  </Tab>
  <Tab value="Lambda de bloque">

```csharp
validar += (int numero) =>
{
    bool resultado = numero > 10;
    Console.WriteLine($"... mayor que 10: {resultado}");
    return resultado;
};
```

Parámetros, `=>` y un bloque con `return`. Sin parámetros: `() => { ... }`.

  </Tab>
  <Tab value="Lambda de expresión">

```csharp
validar += (int numero) => numero > 20;
```

Una sola expresión: su valor es lo que se devuelve.

  </Tab>
</Tabs>

- El método anónimo y la lambda de bloque hacen **lo mismo**; la lambda es la forma moderna y más corta. En clase se compararon las dos sintaxis una al lado de la otra.
- En los dos casos va un **`;` después de la llave de cierre**: es el final de la instrucción `validar += ...;`.
- Al pasar el ratón por `delegate`, Visual Studio llamó al método anónimo <Dudoso nota="Es lo que pone el tooltip en la captura; no está claro si se refiere al método anónimo o a otra cosa.">"lambda expression"</Dudoso>.
- Durante la clase se probó también una lambda "menor que 100" que no se quedó en el código.

En Java la lambda de expresión sería `numero -> numero > 20`: cambia la flecha.

## Miembros con cuerpo de expresión

<DeClase fecha="18/11" proyecto="Clase1" nota="EsImpar en Validador.cs" />

La flecha `=>` también sirve para escribir **un método normal** en una línea, cuando su cuerpo es una sola expresión. En clase se creó `EsImpar` reutilizando `EsPar`:

<Comparar titulo="EsImpar en Validador.cs">
  <Lado tipo="evitar" titulo="Primer intento: no compila">

```csharp
public static bool EsImpar(int x) => { ... }
```

Después de `=>` en un método tiene que ir **una expresión**, no un bloque entre llaves. Daba errores.

  </Lado>
  <Lado tipo="bien" titulo="Como quedó">

```csharp
public static bool EsImpar(int x) => !EsPar(x);
```

Equivale a `{ return !EsPar(x); }`.

  </Lado>
</Comparar>

- El primer intento <Dudoso nota="El cursor tapa el operador; se supone %.">usaba `%`</Dudoso> dentro de las llaves.
- Como `EsImpar` llama a `EsPar`, al usarlo también se escribe la línea de `EsPar`. Por ejemplo, `EsImpar(7)` escribe *"El resultado de la funcion EsPar para 7 es: False"* y devuelve `true`.
- El PDF usa la misma forma en sus ejemplos: `static int Sumar(int a, int b) => a + b;`.

## Lambdas que usan variables de fuera

Una lambda (o un método anónimo) puede **leer y modificar variables locales** del código que la rodea. Se llama **captura de variables** o *closure*. En clase se vio a fondo el 19/11 con un contador de segundos: lo tienes en [Eventos](/docs/2-dam/desarrollo-de-interfaces/csharp/eventos#captura-de-variables).

```csharp title="Program.cs"
bool valida;
do
{
    Console.Write("\nNota (0 a 10): ");
    int nota = Convert.ToInt32(Console.ReadLine());

    ValidadorNotas.ValidarNota validar = delegate (int n)
    {
        bool r = n >= 0 && n <= 10;
        Console.WriteLine($"¿Está entre 0 y 10? {r}");
        return r;
    };
    validar += (int n) =>
    {
        bool r = n >= 5;
        Console.WriteLine($"¿Está aprobada? {r}");
        return r;
    };

    valida = ValidadorNotas.Ejecutar(validar, nota);
} while (!valida);

public class ValidadorNotas
{
    public delegate bool ValidarNota(int n);

    public static bool Ejecutar(ValidarNota validar, int n)
    {
        bool resultado = true;
        foreach (ValidarNota paso in validar.GetInvocationList())
        {
            resultado = resultado && paso(n);
        }
        Console.WriteLine(resultado ? "Nota válida" : "Nota no válida, prueba otra vez");
        return resultado;
    }
}
```

Con 12 solo se escribe la primera comprobación (False) y vuelve a pedir; con 4 se escriben las dos; con 7 se acepta.

  </Solucion>
</Ejercicio>
