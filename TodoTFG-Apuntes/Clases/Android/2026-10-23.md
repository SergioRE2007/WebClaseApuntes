## 2. Conceptos y patrones

- **ViewModel con Hilt**: `@HiltViewModel` y `@Inject constructor(private val _repository: TaskRepository)`. El ViewModel solo conoce la interfaz del repositorio.
- **Estado encapsulado**: `private val _state = MutableStateFlow<...>(...)` y `val state: StateFlow<...> get() = _state.asStateFlow()`. La UI puede leer el estado, pero no cambiarlo. Convención: `_` para la propiedad privada.
- **Estados de pantalla sellados**. Se usan dos variantes:
  - `sealed interface` con `object X : State` (en la pantalla de crear).
  - `sealed class` con `object X : State()` o `class X(val ...) : State()` (en la de lista). En una `sealed class` hay que llamar al constructor del padre (`()`). En una `sealed interface`, no.
- **`object` y `class` dentro del `when`**: un `object` se compara directamente (`TaskListScreenState.Loading ->`). Una `class` necesita `is` (`is TaskListScreenState.Success ->`). El `when` sobre un tipo sellado tiene que ser **exhaustivo**.
- **Smart cast frente a cast explícito**: el profesor usa `(state as TaskListScreenState.Success).tasks`. El smart cast no funciona porque `state` es una propiedad delegada con `by`. Esto lo deduzco; él no lo explica en las capturas.
- **Corrutinas**: `viewModelScope.launch { }`, repositorio con funciones `suspend` y `delay()` para simular la latencia.
- **Ciclo de carga**: `Loading`, luego `readAll()` y luego `Success(tasks)`. `load()` es pública para poder recargar.
- **Compose**: `collectAsStateWithLifecycle()` y `by`, `Scaffold` con `innerPadding`, `Modifier.consumeWindowInsets(innerPadding).padding(innerPadding)`, `FloatingActionButton` con `Icon(painterResource(...))`, `LazyColumn` con `items(items, key = { it.id })` y `item { }`.
- **State hoisting**: una pantalla *stateless* (recibe `isLoading` y `tasks`) y una *stateful* (tiene el ViewModel). La navegación llega por callbacks (`toCreate: () -> Unit`, `toDetail: (Int) -> Unit`), así que la pantalla no conoce el `navController`.
- **`LazyListScope`**: dentro de `LazyColumn { }` no se pueden llamar composables directamente. Hay que meterlos en `item { }` o en `items { }`.
- **`TODO()`**: marca código pendiente. Compila porque devuelve `Nothing`, pero lanza una excepción si se ejecuta.
- **Depuración en Android Studio**: breakpoints, Evaluate expression, Threads & Variables, Frames (se ve la pila de la corrutina `invokeSuspend` de `TaskCreateViewModel`), Resume y Step over.

class TaskListViewModel @Inject constructor(
    private val _repository: TaskRepository
) : ViewModel() {

    //val state: StateFlow<List<Task>> = _repository.tasks as StateFlow<List<Task>>
    private val _state = MutableStateFlow<TaskListScreenState>(TaskListScreenState.Loading)
    val state: StateFlow<TaskListScreenState>
        get() = _state.asStateFlow()

    init {
        load()
    }

    fun load() {
        viewModelScope.launch {
            _state.value = TaskListScreenState.Loading
            val tasks = _repository.readAll()
            _state.value = TaskListScreenState.Success(tasks)
        }
    }
}

    object Initial : TaskListScreenState()
    object Loading : TaskListScreenState()
    class Success(val tasks: List<Task>) : TaskListScreenState()
    class Error(val message: String) : TaskListScreenState()
}
