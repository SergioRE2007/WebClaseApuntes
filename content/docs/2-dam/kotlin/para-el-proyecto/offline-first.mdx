Es la idea que se empezó el 09/11 y el 16/11 y no se llegó a ver entera: **la pantalla solo lee de Room** y la red solo sirve para **rellenar Room**. Si no hay internet, la app enseña lo último que guardó en vez de quedarse vacía o cerrarse. A esto se le llama *offline first*.

<Callout type="idea" title="Lo que vas a aprender">
  - Qué se hizo en clase y qué piezas no se llegaron a ver.
  - Un repositorio que expone un `Flow` de Room y un `refresh()` que copia de la API a Room.
  - Un ViewModel que junta los datos y el error con `combine` y rellena el estado `Error`.
  - Por qué se captura `IOException` y no `Exception`.
</Callout>

## Lo que se vio en clase

<DeClase fecha="09/11" proyecto="PokeApp2627" nota="y el 16/11, un fragmento de 3 minutos ya con Room" />

El 09/11, en la PokeApp, el repositorio pasó a recibir **dos DataSource**: el remoto (Retrofit) y uno local, primero en memoria. El local es la **fuente de verdad** y `refresh()` copia del remoto al local. El ViewModel ya no usa `MutableStateFlow` + `init`: construye su estado con `map` + `stateIn` sobre el `Flow` del repositorio.

```kotlin title="PokemonRepositoryImpl.kt (09/11)"
interface PokemonLocalDataSource {
    val pokemons: Flow<List<Pokemon>>
    suspend fun save(pokemons: List<Pokemon>)
}

class PokemonInMemoryDataSource @Inject constructor() : PokemonLocalDataSource {
    private val _pokemons: MutableList<Pokemon> = mutableListOf()
    override val pokemons: Flow<List<Pokemon>> = flow { emit(_pokemons) }
    override suspend fun save(pokemons: List<Pokemon>) {
        _pokemons.clear()
        _pokemons.addAll(pokemons)
    }
}

class PokemonRepositoryImpl @Inject constructor(
    private val _remoteDataSource: PokemonRemoteDataSource,
    private val _localDataSource: PokemonLocalDataSource,
) : PokemonRepository {
    override val pokemons: Flow<List<Pokemon>> = _localDataSource.pokemons
    override fun observePokemon(id: Int): Flow<Pokemon?> = _localDataSource.observePokemon(id)

    init {
        runBlocking { refresh() }
    }

    suspend fun refresh() {
        val remotePokemons = _remoteDataSource.readAllPokemon()
        _localDataSource.save(remotePokemons)
    }
}
```

```kotlin title="PokemonListViewModel.kt (09/11)"
@HiltViewModel
```

Cómo se intentó hacer la carga inicial en el `init` del repositorio:

- `withContext` no sirve: `init` no es `suspend`, y una función `suspend` solo se llama desde una corrutina o desde otra `suspend`.
- `CoroutineScope(Dispatchers.IO).launch` dejaba **la pantalla en blanco**.
- `runBlocking` funcionaba, pero **bloquea el hilo** hasta que responde la red. Se usó como solución provisional.
- Se explicó por qué no usar `GlobalScope`: no está ligado a ningún ciclo de vida.

El 16/11 se vio la misma app ya con Room (`PokemonLocalDBDatasource`, `PokemonDao`, `PokemonEntity`) y el **Database Inspector** (View → Tool Windows → App Inspection) con la tabla `pokemon` llena. El `init { runBlocking { refresh() } }` aparece **comentado**. El `runBlocking` del repositorio es una de las [prácticas raras](/docs/2-dam/kotlin/para-el-proyecto/practicas-raras) que no conviene copiar.

Lo de clase, paso a paso, está en [Offline-first: el repositorio con fuente remota y local](/docs/2-dam/kotlin/datos/offline-first).

Notas sobre este código:

- <Dudoso nota="Se usa en el repositorio, pero en las capturas no sale declarado ni en el LocalDataSource ni en la interfaz del repositorio.">`observePokemon(id)`</Dudoso> no se ve implementado ni en el LocalDataSource ni en la interfaz del repositorio: tal como está, el fragmento no compila.
- No se ve la explicación del profesor de por qué `CoroutineScope(Dispatchers.IO).launch` dejaba la pantalla en blanco. <Dudoso nota="Es una deducción de quien hizo los apuntes, no una explicación de clase.">Probablemente es porque `flow { emit(_pokemons) }` emite una sola vez</Dudoso>: si la pantalla lo lee antes de que llegue la red, recibe la lista vacía y no se entera de los cambios.

La clave es el penúltimo paso: **los datos nunca van de la API a la pantalla directamente**. Siempre pasan por Room, y la pantalla se entera porque observa Room.

### El repositorio

<Recorrido
  titulo="ProductoRepository.kt"
  lenguaje="kotlin"
  codigo={`data class Producto(
    val id: Int,
    val nombre: String,
    val precio: Double,
    val categoriaId: Int
)

fun ProductoEntity.toModel() = Producto(id, nombre, precio, categoriaId)

fun ProductoDto.toEntity() = ProductoEntity(
    id = id,
    nombre = nombre,
    precio = precio.toDouble(),
    categoriaId = categoria.id
)

fun CategoriaDto.toEntity() = CategoriaEntity(id = id, nombre = nombre)

interface ProductoRepository {
    val productos: Flow<List<Producto>>
    suspend fun refresh()
}

class ProductoRepositoryImpl @Inject constructor(
    private val dao: TiendaDao,
    private val api: TiendaApi
) : ProductoRepository {

    override val productos: Flow<List<Producto>> =
        dao.observeProductos().map { lista -> lista.map { it.toModel() } }

    override suspend fun refresh() {
        val respuesta = api.getProductos()
        val pagina = respuesta.body()
        if (!respuesta.isSuccessful || pagina == null) {
            throw IOException("La API respondió \${respuesta.code()}")
        }
        dao.upsertCategorias(pagina.items.map { it.categoria.toEntity() }.distinctBy { it.id })
        dao.upsertProductos(pagina.items.map { it.toEntity() })
    }
}`}
>
  <Paso lineas="1-6" titulo="El modelo de la app">
    `Producto` es lo que ve la interfaz. No es ni la entidad de Room ni el DTO de la API, igual que el `Pokemon` de clase.
  </Paso>
  <Paso lineas="8-17" titulo="Los mappers">
    Funciones de extensión, como el `toModel()` de clase: de entidad a modelo y de DTO a entidad. `precio.toDouble()` porque Prisma manda los `Decimal` como texto en el JSON (`"59.9"`), y por eso el DTO lo tiene como `String`.
  </Paso>
  <Paso lineas="19-22" titulo="La interfaz">
    Lo que conoce el ViewModel: un `Flow` con los productos y una función para refrescar.
  </Paso>
  <Paso lineas="29-30" titulo="Leer siempre de Room">
    El primer `map` es el de `Flow` (transforma cada emisión) y el segundo, el de `List` (transforma cada elemento). Cada vez que cambia la tabla, sale la lista nueva ya convertida a modelo.
  </Paso>
  <Paso lineas="32-37" titulo="Sin !!">
    En vez del `body()!!` de clase, se comprueba si la respuesta fue bien y que el cuerpo no sea `null`. Si no, se lanza una `IOException` que recoge el ViewModel.
  </Paso>
  <Paso lineas="38-39" titulo="Primero los padres">
    Primero las categorías (sin repetir, con `distinctBy`) y después los productos. Al revés, la clave ajena no deja guardar productos de categorías que todavía no existen.
  </Paso>

### El ViewModel

El ViewModel lanza `refresh()` en su `init`, **dentro de `viewModelScope.launch`**. Así no se bloquea nada y la corrutina se cancela sola si se cierra la pantalla.

<Recorrido
  titulo="ProductosViewModel.kt"
  lenguaje="kotlin"
  codigo={`sealed interface ProductosUiState {
    data object Loading : ProductosUiState
    data class Success(val productos: List<Producto>) : ProductosUiState
    data class Error(val mensaje: String) : ProductosUiState
}

@HiltViewModel
class ProductosViewModel @Inject constructor(
    private val repository: ProductoRepository
) : ViewModel() {

    private val _error = MutableStateFlow<String?>(null)

    val uiState: StateFlow<ProductosUiState> =
        combine(repository.productos, _error) { productos, error ->
            if (productos.isEmpty() && error != null) {
                ProductosUiState.Error(error)
            } else {
                ProductosUiState.Success(productos)
            }
        }.stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5_000L),
            initialValue = ProductosUiState.Loading
        )

    init {
        refresh()
    }

    fun refresh() {
        viewModelScope.launch {
            try {
                _error.value = null
                repository.refresh()
            } catch (e: IOException) {
                _error.value = e.message ?: "No hay conexión"
            }
        }
    }
}`}
>
  <Paso lineas="1-5" titulo="Los estados">
    Como los estados sellados de clase. `data object` es un `object` con `toString()` legible; se usa igual en el `when`.
  </Paso>
  <Paso lineas="12" titulo="El error, aparte">
    El error no viene de Room, así que va en su propio `MutableStateFlow`, que empieza en `null`.
  </Paso>
  <Paso lineas="14-20" titulo="combine">
    Junta dos `Flow` (lo que hay en Room y el error) en un solo estado. Se recalcula cada vez que cambia **cualquiera** de los dos.
  </Paso>
  <Paso lineas="16-17" titulo="Error solo si no hay nada">
    Solo se enseña `Error` si no hay nada guardado. Si hay datos viejos en Room, se enseñan aunque falle la red: eso es *offline first*.
  </Paso>
  <Paso lineas="21-25" titulo="stateIn, como en clase">
    Igual que el 09/11: convierte el `Flow` en un `StateFlow` que vive en `viewModelScope`, deja de escuchar 5 segundos después de que nadie lo observe y empieza en `Loading`.
  </Paso>
  <Paso lineas="27-29" titulo="Carga al crearse">
    El `init` del ViewModel, no el del repositorio. Así se sustituye el `runBlocking` de clase.
  </Paso>
  <Paso lineas="31-40" titulo="Capturar la IOException">
    Es lo que lanza Retrofit cuando no hay red (y la que lanza el repositorio si la API responde mal). Con `catch (e: Exception)` se capturaría también la cancelación de la corrutina, que no se debe tapar.
  </Paso>
</Recorrido>

### La pantalla

```kotlin title="ProductosScreen.kt"
@Composable
fun ProductosScreen(
    onAnadir: () -> Unit,
    modifier: Modifier = Modifier,
    viewModel: ProductosViewModel = hiltViewModel()
) {
    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    when (val estado = uiState) {
        ProductosUiState.Loading -> CircularProgressIndicator(modifier)
        is ProductosUiState.Error -> Text(estado.mensaje, modifier)
        is ProductosUiState.Success -> ListaProductos(estado.productos, onAnadir, modifier)
    }
}
```

- `when (val estado = uiState)` guarda el valor en una variable local, y así Kotlin hace el *smart cast* solo: no hace falta el `(state as TaskListScreenState.Success).tasks` de clase.
- `ListaProductos` es tu composable con la `LazyColumn`.
- En el estado `Error` puedes poner un botón "Reintentar" con `onClick = viewModel::refresh`.

## Pruébalo

Quita el wifi, refresca, borra los datos de la app… y mira qué estado ve la pantalla en cada caso:

<SimuladorOfflineFirst />

Lo que tienes que ver en la demo:

- Con datos en Room y **sin red**, `refresh()` falla pero la pantalla sigue en `Success` con lo de antes.
- Con Room **vacía y sin red**, la pantalla pasa a `Error`.
- Si cambia un precio en la API, la pantalla no se entera hasta el siguiente `refresh()`: lo que se ve es siempre lo que hay en Room.

<Callout type="warn" title="La lista vacía no es un error">
  Room emite su lista enseguida, aunque esté vacía. Por eso, mientras llega la primera respuesta de la API, la pantalla ve `Success` con la lista vacía y no `Loading`. Pon un texto del tipo "Todavía no hay productos" cuando `productos` esté vacía, en vez de una pantalla en blanco.
</Callout>

```kotlin title="ProductoRepository.kt"
// En la interfaz
fun observeProducto(id: Int): Flow<Producto?>

// En ProductoRepositoryImpl
override fun observeProducto(id: Int): Flow<Producto?> =
    dao.observeProducto(id).map { it?.toModel() }
```

```kotlin title="ProductoDetalleViewModel.kt"
sealed interface DetalleUiState {
    data object Loading : DetalleUiState
    data object NoExiste : DetalleUiState
    data class Success(val producto: Producto) : DetalleUiState
}

@HiltViewModel
class ProductoDetalleViewModel @Inject constructor(
    repository: ProductoRepository,
    savedStateHandle: SavedStateHandle
) : ViewModel() {
    private val id = savedStateHandle.toRoute<Ruta.DetalleProducto>().id

    val uiState: StateFlow<DetalleUiState> = repository.observeProducto(id)
        .map { producto ->
            if (producto != null) DetalleUiState.Success(producto) else DetalleUiState.NoExiste
        }
        .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000L), DetalleUiState.Loading)
}
```

  `it?.toModel()` solo llama a `toModel()` si `it` no es `null`; si lo es, el resultado es `null`. Esta es justo la pieza `observePokemon(id)` que en clase no se llegó a ver.

  </Solucion>
</Ejercicio>
