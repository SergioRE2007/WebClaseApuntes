Hay datos que no merecen una tabla de Room: si el usuario quiere el modo oscuro, el idioma, el último filtro que usó o el token de la sesión. Para esas **preferencias** pequeñas está **DataStore**, que las guarda en un archivo del móvil y las devuelve como un `Flow`. Sustituye a las antiguas `SharedPreferences`.

El 18/11 se usó **DataStore Preferences** para guardar el modo oscuro en una pantalla de ajustes nueva de la app de tareas.

## Por qué no basta con el estado de Compose

El estado de un composable o de un ViewModel vive en memoria: cuando la app se cierra del todo, se pierde. Una preferencia tiene que **sobrevivir** a eso. Prueba a encender los tres interruptores y gira el móvil o cierra la app:

<PersistenciaDataStore />

- `remember` se pierde incluso al **girar** el móvil, porque la Activity se vuelve a crear.
- `rememberSaveable` sobrevive al giro, pero no a **cerrar la app** del todo (quitarla de Recientes).
- **DataStore** lo escribe en un archivo, así que sigue ahí al volver a abrir. Al arrancar, durante un instante el `Switch` enseña el `initialValue` del `stateIn` (`false`), hasta que DataStore termina de leer el archivo.

`remember` y `rememberSaveable` se vieron el 07/10 y están en [Estado y recomposición](/docs/2-dam/kotlin/compose/estado-y-recomposicion).

## 1. El DataSource: leer y escribir con DataStore

La implementación recibe un `DataStore<Preferences>` por el constructor. Ese objeto es el que da acceso al archivo de preferencias.

```kotlin title="features/task/settings/data/local/SettingsDatasource.kt"
interface SettingsDatasource {
    val darkMode: Flow<Boolean>
    suspend fun setMode(mode: Boolean)
}
```

<Recorrido
  titulo="features/task/settings/data/local/SettingsDataStore.kt"
  lenguaje="kotlin"
  codigo={`class SettingsDataStore @Inject constructor(
    private val dataStore: DataStore<Preferences>
) : SettingsDatasource {

    private val uiMode = booleanPreferencesKey(name = "ui_mode")

    override val darkMode: Flow<Boolean>
        get() = dataStore.data.map { preferences -> preferences[uiMode] ?: false }

    override suspend fun setMode(mode: Boolean) {
        dataStore.updateData { preferences ->
            preferences.toMutablePreferences().also {
                it[uiMode] = mode
            }
        }
    }
}`}
>
  <Paso lineas="1-3" titulo="Recibe el DataStore">
    Hilt le pasa el `DataStore<Preferences>`. De dónde sale no se ve en clase (ver más abajo).
  </Paso>
  <Paso lineas="5" titulo="Una clave tipada">
    `booleanPreferencesKey(name = "ui_mode")` crea la clave con su tipo: con ella, leer da un `Boolean?` y escribir solo acepta `Boolean`. Hay una función por tipo (`stringPreferencesKey`, `intPreferencesKey`…).
  </Paso>
  <Paso lineas="7-8" titulo="Leer: data.map">
    `dataStore.data` es un `Flow<Preferences>` que emite cada vez que cambian las preferencias. Con `map` se saca solo el valor de la clave. Si nunca se ha guardado, `preferences[uiMode]` es `null` y el elvis `?: false` da el valor por defecto.
  </Paso>
  <Paso lineas="10-11" titulo="Escribir: updateData">
    `updateData` es `suspend`: recibe las preferencias actuales y espera que la lambda **devuelva las nuevas**. DataStore las guarda en el archivo y `data` vuelve a emitir.
  </Paso>
  <Paso lineas="12-14" titulo="toMutablePreferences().also">
    `Preferences` es de solo lectura, así que se hace una copia mutable, se cambia la clave dentro de `also { }` y `also` devuelve esa misma copia, que es lo que tiene que devolver la lambda.
  </Paso>
</Recorrido>

### La lambda de `updateData` tiene que devolver algo

Al principio de la clase el profesor prueba en directo a escribir `setMode` guardando la copia en una variable, y el IDE marca un error. Las capturas no enseñan esa versión entera; por lo que se describe, era algo así:

<Comparar titulo="Escribir en updateData">
  <Lado tipo="evitar" titulo="Lo que se probó (no compila)">

```kotlin
dataStore.updateData { preferences ->
    val mutable = preferences.toMutablePreferences()
    mutable[uiMode] = mode
}
```

En Kotlin, una lambda devuelve **su última expresión**. Aquí la última línea es una asignación, que no devuelve nada, y `updateData` espera unas `Preferences`.

  </Lado>
  <Lado tipo="bien" titulo="Lo que quedó en clase">

```kotlin
dataStore.updateData { preferences ->
    preferences.toMutablePreferences().also {
        it[uiMode] = mode
    }
}
```

`also` ejecuta el bloque con el objeto como `it` y **devuelve el objeto**. La lambda acaba devolviendo la copia ya cambiada.

  </Lado>
</Comparar>

<NoDadoEnClase titulo="La forma corta: edit">

```kotlin
override suspend fun setMode(mode: Boolean) {
    dataStore.edit { preferences -> preferences[uiMode] = mode }
}
```

  `edit { }` hace lo mismo que el `updateData { toMutablePreferences().also { } }` de clase: te da directamente las preferencias mutables y no tienes que devolver nada.

</NoDadoEnClase>

## 4. El ViewModel

```kotlin title="features/task/settings/ui/SettingsViewModel.kt"
@HiltViewModel
class SettingsViewModel @Inject constructor(
    private val settingsRepository: SettingsRepository,
) : ViewModel() {

    val uiState: StateFlow<SettingsUiState> = settingsRepository.settings
        .map<Boolean, SettingsUiState> { SettingsUiState(it) }
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(stopTimeoutMillis = 5_000L),
            initialValue = SettingsUiState()
        )

    fun changeMode(mode: Boolean) {
        viewModelScope.launch {
            settingsRepository.setMode(mode)
        }
    }
}

data class SettingsUiState(
    val darkMode: Boolean = false,
)
```

- **Leer**: el mismo `map` + `stateIn` de la PokeApp (ver [Flow y stateIn](/docs/2-dam/kotlin/datos/flow-y-statein)). Aquí el estado es una `data class` con valor por defecto, así que `SettingsUiState()` sirve de `initialValue`.
- **Escribir**: `changeMode()` es una función normal (la llama el `Switch`) que lanza la escritura, que es `suspend`, con `viewModelScope.launch` (ver [Corrutinas](/docs/2-dam/kotlin/datos/corrutinas)).
- El valor de `WhileSubscribed` se lee <Dudoso nota="En otra captura queda ilegible.">`5_000L`</Dudoso> en una captura.

## 5. La pantalla

```kotlin title="features/task/settings/ui/SettingsScreen.kt"
@Composable
fun SettingsScreen(
    modifier: Modifier = Modifier,
    viewModel: SettingsViewModel = hiltViewModel(),

    val uiState by viewModel.uiState.collectAsStateWithLifecycle()
    Scaffold { innerPadding ->
        Row(modifier = Modifier.padding(innerPadding)) {

```

- El `Switch` es **controlado**: no guarda nada, enseña `uiState.darkMode` y avisa al ViewModel cuando el usuario lo toca. Al principio de la clase la pantalla tenía un `var checked = true` local, que en la versión final ya no está.

### El módulo del DataStore <NoDadoEnClase inline />

<NoDadoEnClase>

```kotlin title="core/di/DataStoreModule.kt"
private val Context.dataStore: DataStore<Preferences> by preferencesDataStore(name = "ajustes")

@Module
@InstallIn(SingletonComponent::class)
object DataStoreModule {
    @Provides
    @Singleton
    fun provideDataStore(@ApplicationContext context: Context): DataStore<Preferences> =
        context.dataStore
}
```

- `by preferencesDataStore(name = "ajustes")` crea el archivo `ajustes.preferences_pb` la primera vez que se usa.
- La línea `private val Context.dataStore` va **fuera de cualquier clase**, arriba del archivo. Si se crean dos DataStore con el mismo nombre, la app se cae.

### Llevar el modo oscuro al tema <NoDadoEnClase inline />

En `MainActivity`, por encima de todo, se lee el modo oscuro y se le pasa al tema. Con las clases de clase quedaría así:

```kotlin title="MainActivity.kt"
@AndroidEntryPoint
class MainActivity : ComponentActivity() {

    private val settingsViewModel: SettingsViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            val uiState by settingsViewModel.uiState.collectAsStateWithLifecycle()
            ToDoOfflineFirstTheme(darkTheme = uiState.darkMode) {
                MainNavigation()
            }
        }

```

- `by viewModels()` es la forma de pedir un `@HiltViewModel` desde una Activity; en un composable se usa `hiltViewModel()`. Se usó igual el 13/11 para la Splash Screen.
- La pantalla de ajustes tiene su propio `SettingsViewModel`, pero los dos leen el mismo DataStore: el tema cambia nada más tocar el `Switch`.

## Ejercicios

<Ejercicio titulo="Un contador de aperturas" dificultad="media">
  Añade a `SettingsDataStore` una preferencia `aperturas` (un `Int`) con:

  - `val aperturas: Flow<Int>` que dé 0 si nunca se ha guardado.
  - `suspend fun sumarApertura()` que le sume 1 al valor guardado.

  <Pista>La clave de un entero se crea con `intPreferencesKey`.</Pista>
  <Pista>Dentro de `updateData` tienes las preferencias actuales: lee el valor de ahí antes de escribir el nuevo.</Pista>

  <Solucion>

```kotlin
private val aperturasKey = intPreferencesKey(name = "aperturas")

val aperturas: Flow<Int>
    get() = dataStore.data.map { preferences -> preferences[aperturasKey] ?: 0 }

suspend fun sumarApertura() {
    dataStore.updateData { preferences ->
        preferences.toMutablePreferences().also {
            it[aperturasKey] = (preferences[aperturasKey] ?: 0) + 1
        }
    }
}
```

  Leer y escribir dentro del mismo `updateData` es importante: DataStore hace la operación entera de una vez, así que si se llama dos veces seguidas no se pierde ninguna suma.

  </Solucion>
</Ejercicio>

<Ejercicio titulo="Pantalla de ajustes con dos opciones" dificultad="media">
  Amplía `SettingsUiState` y `SettingsScreen` para que, además de «Dark Mode», haya un segundo `Switch` «Notificaciones». Supón que el repositorio ya tiene `val notificaciones: Flow<Boolean>` y `suspend fun setNotificaciones(valor: Boolean)`. ¿Cómo juntas los dos `Flow` en un solo estado?

  <Pista>Para juntar dos `Flow` en uno hay un operador: `combine(flowA, flowB) { a, b -> ... }`.</Pista>

  <Solucion>

```kotlin
data class SettingsUiState(
    val darkMode: Boolean = false,
    val notificaciones: Boolean = false,
)

val uiState: StateFlow<SettingsUiState> =
    combine(settingsRepository.settings, settingsRepository.notificaciones) { dark, notif ->
        SettingsUiState(darkMode = dark, notificaciones = notif)
    }.stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(stopTimeoutMillis = 5_000L),
        initialValue = SettingsUiState()
    )

fun changeNotificaciones(valor: Boolean) {
    viewModelScope.launch { settingsRepository.setNotificaciones(valor) }
}
```

```kotlin
Column(modifier = Modifier.padding(innerPadding)) {
    Row {
        Text("Dark Mode")
        Switch(checked = uiState.darkMode, onCheckedChange = { viewModel.changeMode(it) })
    }
    Row {
        Text("Notificaciones")
        Switch(checked = uiState.notificaciones, onCheckedChange = { viewModel.changeNotificaciones(it) })
    }
}
```

  `combine` (de `kotlinx.coroutines.flow`) no salió en clase: emite un valor nuevo cada vez que cambia cualquiera de los dos `Flow`.

  </Solucion>
</Ejercicio>
